# Git 分支与代码评审规范

## 分支与任务

`main` 保存经过验证与评审的集成结果。独立任务使用短期分支，命名为 `feat/<task>-<topic>`、`fix/<task>-<topic>`、`chore/<task>-<topic>` 或 `docs/<topic>`；使用英文小写与连字符。例如 `chore/p0-01-engineering-foundation`。

一个分支围绕一个明确交付目标，内部按可独立验收的功能点提交。提交格式与自动提交时机见 [Git 提交规范](git-提交规范.md)。合并时保留清晰的功能提交记录；暂未配置远程仓库时先完成本地提交与检查。

## PR 与评审

PR 使用 [仓库模板](../../.github/pull_request_template.md)，标题采用 Conventional Commits，描述问题、结果、真实任务编号、验证证据和兼容影响。通过相关检查后再提交评审。

Reviewer 根据任务所属版本的范围和验收标准确认实现，再按 [前端规范](前端代码规范.md)、[后端规范](后端代码规范.md) 和 [统一契约](../architecture/统一契约与跨版本演进规则.md) 核对适用规则。公共包和 API 变化覆盖受影响消费者；文档变更检查引用与示例。

安全关键功能至少由一名非作者 Reviewer 审查，开发者不独立验收自己负责的身份、ACL、凭据或删除等安全关键行为。记录评审结论与未解决问题，评审通过后合并。

## 远程配置状态

当前只建立本地分支、PR 模板与 CI 配置。远程仓库、分支保护和 PR 的实际执行状态以服务端配置为准；提交与检查通过不代表已经推送、评审或合并。
