# 后端代码规范

日期：2026-11-24。适用于 FastAPI 后端、业务模块、基础设施 Adapter 和独立 Worker。本文维护代码分层、类型、资源授权、事务、异步执行及验证规则；具体版本、配置和命令在实际源码仓维护。

工程组织依据 [ADR-0014](../adr/0014-monorepo-and-independent-frontend-apps.md) 和 [V1.0 代码结构](../plan/V1.0-MVP/05-code-structure-and-backlog.md)，API、字段、状态和跨版本兼容依据 [统一契约](../architecture/统一契约与跨版本演进规则.md)。所有版本采用单一企业内部部署，企业内主体与资源权限继续执行；后续 Agent/Workflow/预算账本/灾备要求按目标版本实现，不自动成为 V1.0 必交付。

| 层 | 职责与依赖 |
|---|---|
| API | HTTP/DTO 校验、可信身份解析、调用应用用例及错误映射；不直接执行 SQL、ES DSL 或供应商 SDK |

| Infrastructure/Adapter | 实现数据访问与第三方协议，应用可信查询范围、并发约束及技术错误转换 |
| Worker | 领取任务、重建可信上下文、调用 Application、确认/重试；复杂业务规则保留在业务模块 |

模块通过明确的 Application/Contract 访问能力，不读取其他模块的 ORM Model 或私有 Repository。RAG、Model Gateway、Tool Gateway、Identity/Policy 和生命周期能力沿用既有接口，Agent 通过 Retriever/Gateway 使用能力，不直接连接 ES 或业务数据库。

接口除类型外应明确调用前提、授权来源、状态/幂等、错误、超时和事务拥有者。SDK、网络、数据库、时钟等变化点通过 Adapter 提供；只抽取真实复用或替换需要的接口，不为转发一行代码额外套多层抽象。

## 3. 命名、函数与类型

- 文件/模块/函数/变量用 snake_case，类和类型用 PascalCase，常量用 UPPER_SNAKE_CASE；内部导入使用实际 app 包路径，避免通配导入或运行时修改 sys.path。
- 单下划线表达非公开约定；双下划线主要用于名称改写，不提供授权或凭据保护。
- 函数按业务职责组织。约 60 行或超过 5 个参数时检查职责与调用接口，不作为强制拆分门槛；参数对象依含义使用 dataclass、值对象或 DTO。
- 对公共函数、模块接口及关键业务路径声明输入/返回类型。Pydantic 用于边界校验，领域实体和值对象可以使用普通类/dataclass；业务模块不因参数数量而全部改用 Pydantic。
- `Optional[T]` 等价于 `T | None`，Union 表达已知候选类型，不代表任意未知数据。外部未知值先按 object/明确 JSON 类型接收，再校验缩窄；Any 仅在受限 SDK Adapter 等必要位置使用并记录原因。
- 公共配置与事件按正式 Schema 校验，拒绝未知主版本；DTO、领域对象与存储结构有显式映射，类型断言不能替代运行时校验。
- 组合优先，ABC/Protocol 按实际接口选择。允许清晰的局部辅助函数、依赖工厂和闭包；避免晚绑定、共享可变捕获和不必要的嵌套层次。
- 实体、DTO 和配置快照按明确规则变更。纯计算优先返回新值；实体状态迁移、事务内聚合修改等允许受控变更，不修改调用方未知的共享对象。
- `__init__` 完成赋值与不变量校验；网络连接、连接池和外部资源在生命周期/装配阶段创建。显式定义实例、类和静态方法，不按命名风格强制改变职责。
- 重要接口使用简洁 Docstring，说明前提、结果、错误、幂等及副作用；注释解释取舍和原因，不逐行复述代码。

## 4. 身份、检索与可信资源范围

身份、角色、资源 ACL、环境及 Policy 由可信服务端计算。AccessContext 与 Policy Decision 从认证/授权流程构造；普通 API 参数、Prompt、模型工具参数和 MQ 消息头都不能自行授予权限。缺少必需身份或资源授权时拒绝。

检索使用 [V1.0 Retriever Contract](../plan/V1.0-MVP/01-rag-engine-detailed-design.md)：RetrievalRequest/Result 保留 query、kb_ids、filters、服务端 access_context、top_k、config_version、trace_id 等既有语义。客户端只提供允许的业务筛选；Application/Policy 验证资源，Search Adapter 将业务筛选与强制 ACL 条件组合为 ES 查询，不能用用户 filter_expr 替换授权限定。

权限决策属于 Policy/业务用例，Repository 仍须应用可信资源范围、关系校验及必要数据库约束。“不做业务决策”不能解释为省略查询中的资源授权限制；检索、Parent Context、引用、对象下载、工具调用与恢复均重新验证适用当前权限。

以下完整标准库示例只演示授权选择和服务端上限检查，不替代实际 AccessContext、RetrievalRequest 或完整 ACL 实现。authorized_kb_ids 和 max_top_k 必须来自可信服务端；调用方不能从模型/客户端复制这些值。

```python
from collections.abc import Sequence


class ResourceScopeDeniedError(Exception):
    """请求包含当前主体未获准访问的知识库。"""


def validate_kb_selection(
    requested_kb_ids: Sequence[str],
    authorized_kb_ids: frozenset[str],
    *,
    top_k: int,
    max_top_k: int,
) -> tuple[str, ...]:
    """校验资源选择和当前上限，返回保留输入顺序的唯一 ID。

    Raises:
        ValueError: 选择为空或 top_k 超出服务端范围。
        ResourceScopeDeniedError: 请求包含未授权资源。
    """
    if not requested_kb_ids:
        raise ValueError("knowledge base selection is required")
    if not 1 <= top_k <= max_top_k:
        raise ValueError("top_k is outside the permitted range")
    if not set(requested_kb_ids).issubset(authorized_kb_ids):
        raise ResourceScopeDeniedError("knowledge base access denied")
    return tuple(dict.fromkeys(requested_kb_ids))
```

校验成功后通过原 Retriever Contract 传递可信上下文及业务筛选，实际读写继续执行当前授权。本例没有实现外部调用或新增 API 错误枚举；API 层按已定义的校验/权限错误映射返回。

## 5. 生命周期、同步/异步与事务

### 5.1 资源与执行方式

- 连接池、HTTP 客户端、模型/存储 Adapter 在 FastAPI lifespan 或已定义 Worker 生命周期中创建和关闭，避免逐请求建池或泄露连接。每个独立进程按自身生命周期装配资源。
- Session、事务和请求上下文按用例/任务隔离，完成后释放；共享连接池不代表可共享一个事务/Session。若使用 SQLAlchemy，Session/AsyncSession 不在并发请求或任务间共用。
- async def 中使用异步 I/O 或已验证的有界线程桥接；同步 SDK 不直接阻塞事件循环。Docling/MinerU 等解析及重计算按独立 Worker/执行池处理。
- Celery 任务的同步/异步入口按实际执行池和 Adapter 能力冻结，不假定 Celery 会自动 await 协程；事件循环和客户端不跨不兼容线程/进程复用。
- 超时、并发、请求体/候选规模等限制来自版本化配置并贯穿入口、队列和外部调用。局部取消或超时不证明外部调用未提交。

### 5.2 事务拥有者

Application 用例或其显式 Unit of Work 拥有事务完成权。API 与 Worker 调用同一用例；Repository 参与传入事务，不在各方法中自行 commit，失败按原子性要求 rollback。自动提交、批处理和独立操作若确有需求，在接口中明确各自事务范围。

需要共同成立的实体变更、状态/幂等记录、事件意图与可靠审计按目标版本在同事务或已定义可靠机制闭合。唯一约束、外键、CAS/锁与租约验证实际并发，不能用“先查询再插入”或进程内锁替代数据库保证。

外部模型/工具/对象/业务系统网络调用不长期占用数据库事务。先持久化受控操作意图与当前状态 → 事务外调用 → 按原 Key/Attempt 和事实写回；跨 DB、ES、对象存储和队列通过持久任务/Outbox/对账修复，不把分布式操作宣称为一个数据库原子事务。

写入结果不确定、事务失败或连接失效时，先释放/恢复有效事务并判断实际结果，再按错误与幂等规则处理。不能复用已经失败的 Session 继续业务查询，也不能凭本地 rollback 宣称外部操作已撤销。

## 6. Worker、消息与副作用可靠性

RabbitMQ/Celery 是任务传输和执行机制，业务事实保存在 PostgreSQL 及受控产物中。Task 通过持久 Job/Run/Instance 引用加载 Owner、状态、快照与期限，重建当前授权；消息引用校验后仍不替代可信身份来源。

- 消息包含稳定任务/事件 ID、版本及必要引用，不携带可自行提升权限的角色、明文 Secret 或整段敏感正文。
- 同一消息重投按原业务 Key 去重，数据库约束和状态条件防并发重复；发送确认丢失、消费确认丢失与 Worker 崩溃均有持久恢复路径。
- 任务提交/派发按已定义 Outbox 或等效机制与业务提交协调，不能在数据库提交前发布“成功”事件。消费确认必须与持久结果/安全恢复点及实际重试配置协调。
- 重试采用明确错误分类、有界退避、最大次数与 Deadline；权限拒绝、参数错误、未知业务效果不默认重试。429/超时等仅在当前契约允许且副作用/预算仍安全时重试。
- 外部操作使用原 operation_key/请求 Key 与保存的参数/版本，未知结果进入 UNKNOWN/受控对账；只有证据支持才重放或执行单独授权的补偿。
- 租约/心跳/fencing_token 防旧 Worker 回写，不能替代外部系统幂等。长审批、事件等待、Checkpoint 等保持持久状态，不依赖 Worker 常驻或内存计时器。
- Task 重放、DLQ、补偿与恢复重新检查当前 Policy、快照、有效期和剩余预算；旧授权失效后不自动提升为管理员继续执行。

持久 Run/Step/Checkpoint、Approval/Action、Timer 与费用账本按 [统一契约第 4/5/10/11 节](../architecture/统一契约与跨版本演进规则.md) 演进。保留既有 UUID、配置快照、幂等 Key、序号与 TTL，功能增量不重建平行事实源。

## 7. 异常、HTTP 与流式协议

| 层 | 错误处理 |
|---|---|
| Domain/模块接口 | 表达稳定业务或接口错误及可处理的失败语义，不暴露 HTTP/供应商细节 |
| Adapter | 将已知技术错误转换为模块接口错误，保留内部 cause；对约束冲突、限流、超时和结果未知分别处理 |
| Application | 根据用例、当前状态、幂等及副作用事实决定失败、回查、重试或补偿 |
| API/Worker | 映射正式错误 Envelope/任务结果，记录关联 ID 和适用日志，不将敏感原始异常返回给用户 |

捕获范围尽量小，使用明确异常及必要的异常链。未知故障在受控入口记录后失败，不以空 except、吞错或默认空结果冒充成功。顶层故障处理可捕获 Exception 以完成错误映射/资源清理，但不把所有未知故障标记为可重试；异步取消按运行环境正确传播。

HTTP 路由沿用 [V1.0 API](../plan/V1.0-MVP/03-database-and-api-design.md) 的 `/api/v1`、UTC、分页与幂等；JSON 错误使用既有 `error.code/message/request_id/retryable/details`，领域 error_code 通过显式映射进入响应。ORM、领域实体和 Secret 不直接序列化为客户端 DTO，响应模型校验适用字段及权限。

SSE 形成正式事件契约：JSON 正确编码、事件边界与适用 sequence 持久化，客户端断开后释放生成器、订阅和连接。长连接不持有数据库事务，断流不自动取消已提交副作用。V1.0 能力、V1.1 Run 补拉及 V1.4 Workflow 事件按各自版本实现；HTTP 响应开始后发生的错误通过协议事件表达，不假定还能改写原 HTTP 状态。

修改 DTO、状态、事件或错误时识别现有消费者，生成 OpenAPI/JSON Schema/迁移 Diff，并验证 frontend/packages/api-client 及受影响 Chat/Admin 应用；不从文档直接改列或重命名已发布字段。

## 8. 配置、隐私、生命周期与恢复

配置按环境与明确 Schema 加载，启动时验证必需项，阈值/模型/Prompt/索引版本按既有不可变快照规则维护。凭据通过 Secret 引用解析、加密和受控访问，明文不进入 DTO、Prompt、配置快照、日志/Trace、消息或源码。

日志关联 request_id、trace_id 和适用 Run/Job/Action/Attempt，异常链留在受控内部记录并脱敏。Trace 展示摘要，业务 Audit 保存必要事实，两者不相互替代；高危身份溯源和敏感内容读取沿用独立授权。

删除/员工撤权覆盖适用原件、解析产物、Chunk、ES、缓存、会话/记忆、对象及关联派生数据，由生命周期用例记录子项结果并验证。依法/制度必要审计与账目按有限范围和保留期管理，不以批量级联删除跳过处理。

恢复与升级重新验证当前身份/资源授权、配置版本、Checkpoint TTL、审批、预算及外部操作结果。V2.0 账本/Journal/Recovery Gate 按其契约实施，数据库恢复、应用回滚或消息重放不抹除已发生业务事实。

## 9. 工具配置与实际验证

项目声明、Python/Ruff/Pyright/pytest 等支持的配置在实际 pyproject.toml 管理，配置路径以工具运行目录为准。pre-commit 使用所需 YAML，CI、容器和环境示例按各自工具维护；不要求全部塞入 pyproject.toml。

以下是可解析的配置片段，仅说明规则位置；Python/工具版本、检查目录、生成代码范围及例外在实际初始化时冻结，不覆盖现有配置。

```toml
[tool.ruff]
line-length = 120

[tool.ruff.lint]
select = ["E4", "E7", "E9", "F", "I", "B", "UP"]

[tool.pyright]
typeCheckingMode = "strict"
```

版本固定后使用一致的 Ruff lint/format 与静态类型基线。对 SDK 动态类型、生成代码或存量升级的必要例外限定到具体路径/规则并记录原因，不用全局忽略隐藏错误。pytest 文件使用源码仓约定的 test_*.py 或 *_test.py，单元/集成/契约/安全等分别组织。

| 变更 | 至少验证的实际行为 |
|---|---|
| Domain/Application | 正常/非法状态、业务不变量、失败路径，测试从模块接口进入 |
| API/DTO/事件 | 校验、序列化、错误/权限、旧消费者与生成制品一致 |
| DB/事务/迁移 | 空库/存量升级、约束、冲突、rollback、数量/引用/快照，适用真实并发 |
| 检索/工具/权限 | 跨主体/KB/关系拒绝、当前授权、注入、引用及 Secret 边界 |
| Worker/外部调用 | 重复投递、丢确认、超时/取消、崩溃、原 Key、结果未知与恢复 |
