# ADR-0011：预算预留与用量结算使用持久账本

并发模型调用、重试、流式取消和缺失 usage 会使“调用后扣费”超过可控预算。设计选择 PostgreSQL 事务维护额度预留与追加用量结算，Redis 承担速率/并发加速而不成为费用唯一事实源；相较只使用缓存计数器，这增加事务及对账成本，但能核验并发准入、重复事件和故障后的欠账。

每个物理调用 Attempt 具有独立 admission/usage 标识，未知提交或未知账单保持预留并进入对账，不因 TTL 到期自动返还。实际金额通过固定的价格/币种快照、usage 来源和调整记录结算；内部预算不冒充外部供应商账单，也不在未知价格下承诺严格费用上界。

方案需通过并发、多级预算、流式取消、供应商账单差异及数据库/缓存故障 POC 后评审。具体 DTO、状态和迁移以统一契约及 V2.0/07 为准，既有 Run/Step 用量仍作为兼容视图保留。
