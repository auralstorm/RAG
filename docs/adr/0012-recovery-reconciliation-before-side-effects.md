# ADR-0012：恢复后先核对外部操作再启用写入

数据库 PITR 或灾备恢复可能丢失恢复点之后的本地操作记录，但外部工单已经创建。设计选择保留独立可恢复的 Side Effect Journal/外部证据，并在恢复模式下暂停新副作用、核对原 Key 后才放行；相比恢复数据库后立即重放队列，这降低恢复期间写可用性，却避免把丢失去重记录变成重复业务操作。

V2.0 的受控写入先取得符合恢复策略的提交意图记录持久化凭证；原 Action/Instance/请求 Key 和外部 operation_key 随 Recovery Set 恢复，结果未知继续对账。凭证的存储、密钥、地域和保留策略需按现有对象存储/审计能力验证，不能凭一次保存成功宣称满足跨区域零丢失。

本 ADR 待业务 RPO/RTO、记录保留、外部查询和实际演练后评审接受；它不改变 V1.4 已记录的业务事实，也不批准恢复过程自动撤销或重做外部动作。
