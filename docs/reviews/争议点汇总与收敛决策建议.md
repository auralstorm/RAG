## 一、修订后的结论

原清单 21 项中，5 项问题主体成立、13 项有事实基础但论证或建议需收窄、3 项不成立。主要风险是目标态/版本定位未对齐、公共实体和升级映射不完整、部分任务与验收口径有张力。文档已有 ADR、Contract 冻结和兼容测试要求，不能再定性为“冻结机制完全缺位”。

本轮以 [统一契约与跨版本演进规则](../architecture/统一契约与跨版本演进规则.md) 统一公共字段、状态、事件、权限和迁移解释，并同步版本详设/Backlog/验收。建立设计权威不能使消费者、数据库或业务取舍自动完成收敛；实施关闭条件仍须有真实制品及验证。

## 四、范围与投入规则

Search Gateway 当前建设深度以既定 Search Adapter 的索引写入、查询、健康检查、权限/版本边界为准。GraphRAG 需业务场景与 POC 后再立项。Multi-Agent 保留原 V1.3 规划，先评审单 Agent 基线与实际协作收益，未证明收益时由产品/架构决定是否延后并同步版本范围。

V1.1 最小审批回调、V1.3 HITL 与 V1.4 企业流程分层建设；前序不依赖未实现的企业审批中心。V1.4/V2.0 详设在立项前补齐，生产副作用和共享多租户启用前完成对应专项安全/可靠性验收。

## 五、实施收敛路径

1. 确认路线图、统一契约和已接受租户模式作为设计基线；实际数据库和调用方盘点后评审运行迁移 ADR。
2. 生成真实 OpenAPI、JSON Schema、Alembic 迁移，明确版本、Owner 和 CI 检查；同步增量文档及兼容入口。
3. 验证 Run/Step/Tool/Approval 去重、状态、配置、预算、TTL、权限、事件补拉及历史评测迁移。
4. 固定评分器和业务阈值，按真实场景完成 Multi-Agent 收益评审及后续立项，不以未经估算的天数/行数或文档减量比例作承诺。

逐项修订位置与剩余工作见 [文档修订与收敛记录](文档修订与收敛记录.md)。本文件不再使用“其余 19 项自动消失”的结论，也不将文档修订视为设计或生产验收已经过关。
