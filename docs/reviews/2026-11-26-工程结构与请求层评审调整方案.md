## 3. 请求层改造方案（保留 fetch，不引入 axios）

### 3.1 背景与决策

- 现状底层是原生 fetch：`createApiClient(baseUrl, fetcher = fetch)`，`fetcher` 可注入（单测不发真实网络）；请求固定 `credentials: 'include'`、`cache: 'no-store'`、`AbortSignal.any([signal, AbortSignal.timeout(10_000)])`；非 2xx 归一为自定义 `HttpError`。
- **决策：不切 axios。** 理由：
  - 现有错误归一、CSRF、响应校验都是项目自定义业务逻辑，换库不减少业务代码；
  - 内网现代浏览器原生 fetch 足够；
  - 保留零三方依赖与可注入可测性；
  - RAG 对话后续大概率做增量流式输出，原生 fetch 的 `ReadableStream` 比 axios（XHR/http adapter）更直接。

### 3.2 目标目录

```text
packages/api-client/src/
├─ http/                         # 纯协议底座，不含业务域
│  ├─ http.ts                   # createHttp / Http 接口 / request·get·post·patch·delete
│  ├─ errors.ts                 # HttpError / responseError / publicError（形状不变）
│  └─ types.ts                  # HttpFetcher / HttpRequestInit / HttpResponse
├─ services/                    # 按域端点函数：请求 + 运行时校验 + 强类型返回
│  ├─ auth.ts                   # configuration / login / me / csrf / refresh / logout
│  ├─ authorization.ts          # capabilities
│  ├─ health.ts                 # getLiveness
│  └─ validation.ts             # isRecord / uuidPattern / 会话与 capability 校验
├─ session-store.ts             # 状态协调层（保留，只换引用方式）
├─ generated/                   # openapi-typescript 产物（不动）
├─ types.ts                     # 对外 DTO 类型重导出，按域分组
└─ index.ts                     # 门面：createApiClient + 类型/错误重导出

apps/admin/src/modules/modelGateway/api/
├─ providers.ts                 # list/get/create/update/delete（迁出共享包）
├─ validation.ts                # isProviderAdminView / providerPage
└─ index.ts                     # 类型与函数对外出口
```

依赖方向：`http ← services ← session-store / 应用`；http 不依赖 services，services 不反向依赖应用。

### 3.3 底座接口（设计要点）

- `createHttp(baseUrl, fetcher?)` 返回 `Http`：`request / get / post / patch / delete`，统一承载：
  - baseUrl 协议校验（http/https、无内嵌用户名密码）、`api/v1/` 前缀拼接；
  - `credentials: 'include'`、`cache: 'no-store'`；
  - `AbortSignal.any([signal, AbortSignal.timeout(timeoutMs)])`，默认 10s；
  - query 由底座统一序列化（删除手写 `URLSearchParams`）；
  - 非 2xx → `responseError` → `HttpError`；
  - 预留 `requestStream(path, init)` 返回 `ReadableStream<Uint8Array>`（本期不实现）。
- `fetcher` 默认原生 `fetch`，可注入，现有测试可测性资产完整保留。

### 3.4 错误契约（硬约束：对外形状不变）

`HttpError` 保持现有字段：`status / requestId / details / message`。

- session-store 按 `error.status === 401/403` 映射状态；
- Hook 按 `error.requestId` 展示；
- 测试按 `toMatchObject({status, message})` 断言。

迁移时以现有测试为回归网，不允许改字段名或类型。

### 3.5 Service 划分

每个 service 是工厂函数，接收 `Http`，返回按域方法集合：

- `createAuthService(http)`：`configuration / login / me / csrf / refresh / logout`；
- `createAuthorizationService(http)`：`capabilities`；
- `getLiveness(http, signal?)`。

校验归属：会话/capability 校验（双端共用）→ `services/validation.ts`；provider 视图校验（仅 admin）→ 随 providers 迁到应用内。`application` 参数统一复用 `ApplicationId`。

### 3.6 providers 迁出 admin

| 内容 | 去向 |
|---|---|
| `list/get/create/update/delete` 函数、provider 变更辅助、admin CSRF 中 providers 相关部分 | `apps/admin/.../api/providers.ts` |
| `isProviderAdminView / providerPage` 校验 | `apps/admin/.../api/validation.ts` |
| `ProviderAdminView / CreateProvider / UpdateProvider / ProviderPageResponse` 等 DTO | 纯类型，继续由 generated 门面导出 |
| 共享包 providers 命名空间、`ProviderMutation/ProviderVersionMutation` 运行时辅助 | 删除 |

admin 侧需调整的引用（实测涉及）：`useProviderList.ts`、`useProviderManagement.ts`、`ProviderManagement.tsx`、`ProviderEditor.tsx`、`providerManagement.test.tsx`；测试 mock 目标从 `vi.spyOn(apiClient.providers, 'list')` 改为应用内 service 模块导出。

### 3.7 过渡期兼容门面

为把改动拆成可回退的小步，共享包门面先保留 `createApiClient`，内部装配拆分后的 service：

```ts
export function createApiClient(baseUrl: string, fetcher?) {
  const http = createHttp(baseUrl, fetcher);
  return {
    http,
    auth: createAuthService(http),
    authorization: createAuthorizationService(http),
    health: { getLiveness: (signal?) => getLiveness(http, signal) },
  };
}
```

- 过渡期两端仍 `apiClient.auth.login(...)`、`createSessionStore(apiClient, 'admin')`，session-store 的 `Pick<…, 'auth' | 'authorization'>` 签名不变；
- 第二步再让应用直接装配所需 service，去掉工厂对象壳（可选，不阻塞本期）。

### 3.8 迁移批次（每批可独立提交、可回退）

1. **抽底座**：`privateRequest/responseError/HttpError` → `http/`，`index.ts` 委托；补 http 单测（成功/非 ok/取消/超时/query 序列化/前缀/凭据头）。行为零变化。
2. **拆 auth/authorization/health service**：闭包改工厂函数，共用校验迁 `validation.ts`；session-store 注入方式不变；跑现有 client/session-store 测试回归。
3. **providers 迁出 admin**：复制函数与校验到应用，删共享包 providers 命名空间，改引用文件与测试 mock；删本地重复 `LoginCredentials`。**改动面最大，单独提交。**
4. **类型门面分组**：`types.ts` 按域重导出，清理 `index.ts` 顶部类型堆叠；generated 产物不动。
5. **接线收敛（可选）**：应用 `apiClient.ts` 直接装配 service，去掉命名空间壳。

### 3.9 明确不做

- 不引入 axios；
- 不改 session-store 状态机（订阅/刷新/多标签锁/过期定时器逻辑原样保留）；
- 不替换数据缓存方案（Hook 手写 `useEffect/useState/AbortController` 是状态层决策，是否上 TanStack Query 见开放项 5.4）；
- 不改后端契约与 OpenAPI 生成产物；
- 本期不实现流式端点，仅在底座预留接口。

## 7. 鉴权链路评审结论（模式保留，后续接入要求）

### 7.1 评审通过的现状设计

- **凭据下发**：登录成功后通过 HttpOnly Cookie 下发 `er_{application}_access`（JWT，HS256，默认 900s）与 `er_{application}_refresh`（随机串，库内只存 SHA-256 digest，支持轮换）；`httponly=True`、`samesite="strict"`、`secure` 按配置、`path="/"`；响应体不返回 token，只给 `user / application / expires_at / csrf_token`。
- **请求携带**：前端 `credentials: 'include'`，浏览器自动带 Cookie；全前端无 `Authorization: Bearer` 头，access/refresh token 不写入 localStorage/sessionStorage；localStorage 仅存不含凭据的会话协调标记。
- **校验**：`/me` 每次查库使撤销实时生效；refresh 轮换并置旧令牌 `consumed_at`；写操作带 `X-CSRF-Token`，服务端 HMAC 比对；`guard_origin` 校验分端 Origin 白名单，拒绝 cross-site，配置禁 `*`。
- **授权**：23 个权限码；系统角色 SUPER_ADMIN / KB_ADMIN / AUDIT_READONLY；可委派仅 `*.read`；`ResourceGrant` 做 kb_id + 主体类型 + READ/MANAGE；`AccessPurpose=chat|admin`，chat 策略上仅允许 `kb.read`；`PolicyEnforcer.load` 构造上下文与快照，`authorize` fail closed 带 reason_code；写操作事务带 policy_version 乐观锁（409）+ savepoint + CSRF + 前后两次 require + 审计前后快照。

### 7.2 后续接入需核查的风险项（非本次重构）

- 其余 KB/文档/检索/对话端点落地时必须接 `RbacService.require`；
- 权限码前后端字符串重复（对应开放项 5.5）；
- OAuth / AuthorizationCodeProvider 协议预留未实现；
- Worker 重建可信上下文未落地；
- 前端授权快照变更生效路径需关注；
- chat ACL 粒度须复用服务端 grants 范围。
