# P1-04 登录与身份映射

日期：2026-11-25。按 [P0-05 已确认口径](P0-05.md)，先实现本地测试身份源、统一身份映射和平台会话，再对接真实企业身份源。本任务分为可独立验证的后端会话与前端接入两部分；完整 P1-04/M1 不因本地测试通过自动关闭。

## P1-04-01 后端本地身份与平台会话

- `IdentityProvider` 是认证来源接口。本地 Adapter 从权限为 0600、属于当前操作系统用户的私密文件读取账号和 PBKDF2-HMAC-SHA256 校验值，每个账号独立 salt、600000 次迭代；未知账号仍执行同等密码计算。密码校验在线程中执行，不阻塞异步请求，也不长期占用数据库事务。
- 默认身份源未配置，`config` 返回 unavailable，登录服务返回 503；只有显式提供 `ENTERPRISE_RAG_LOCAL_IDENTITY_CONFIG_REF` 才启用。production 明确拒绝本地身份配置。账号不会在应用启动或登录时自动创建。
- 本地来源使用 `local`、精确 issuer 和不可猜测的稳定 subject 查 identities，再解析规范 users.id；不按用户名、显示名、email 或相同 UUID 合并。未建映射、来源停用、用户非 ACTIVE 或软删除均拒绝。
- 0003 迁移新增 identity_applications、auth_sessions、auth_refresh_tokens 和 auth_login_budgets。应用访问许可为当前服务端事实，Chat/Admin 会话分别绑定用途、Cookie 名和 JWT audience。identity_applications 只控制应用入口，不授予任何管理操作或 KB 权限；固定角色矩阵和资源 Policy 仍由 P1-05 交付。
- 访问 JWT 使用固定 HS256、`at+jwt` 类型、独立 issuer、每应用 audience，验证签名、必需字段、有效期、nbf/iat、格式和主版本。JWT 只保存会话、主体和身份引用；每次恢复仍核对数据库会话、当前用户、身份和应用许可，不信任 Token 中的角色。
- 默认访问期限 15 分钟，会话绝对期限 24 小时，不因续期延长绝对期限。续期使用独立随机凭证，数据库仅存 SHA-256；原凭证消费后不能再次使用，重放或并发重复续期撤销整个会话。客户端不得盲目重试续期请求，响应丢失时可能需要重新登录。
- Token 仅经 host-only、HttpOnly、SameSite=Strict Cookie 返回；不进入 JSON 或浏览器持久化存储。production Cookie 使用 Secure，本地 HTTP 开发使用非 Secure。Chat/Admin Cookie 名独立；Cookie 不以端口隔离，服务端额外校验当前应用的精确 Origin。
- 登录、续期和登出要求精确来源；跨应用、跨站或缺少 Origin 的写请求拒绝。续期和登出同时要求会话绑定的 CSRF 头；CSRF 值只给同源可读取的会话响应。访问凭证到期后，可通过只读 csrf 接口恢复内存值再续期；该接口不旋转凭证或授予登录。
- 当前用户停用、待离职、离职、身份停用或应用许可撤销均阻止恢复/续期。登出立即撤销服务端会话并删除对应应用 Cookie，不退出另一应用的独立会话。
- 登录预算持久化于数据库，默认同应用账号每 60 秒 5 次、同网络来源每 60 秒 30 次；`make dev-backend` 显式禁用 Uvicorn 代理头改写，不采信请求方的转发 IP。Nginx 同源代理场景在此模式下共享代理连接的网络预算；正式部署需先冻结可信代理链和限流位置，不能直接开放任意转发头。预算键为不可直接反查账号/IP 的派生摘要。成功和失败登录写入现有审计表；成功会话与成功审计在同一事务中提交，审计失败时不建立会话。完整审计应用服务继续由 P1-06 交付。

PyJWT 固定为 2.15.1，核对其官方 API 与 changelog 后沿用白名单算法、issuer/audience、require 与 strict_aud。HS256 安装不引入可选非对称加密依赖；对 SDK 未安装的可选 Key 类型引起的静态成员类型告警，仅在具体调用行忽略，解码结果仍经严格 Pydantic 校验。

## HTTP 入口

以下路径均以 `/api/v1/auth/{application}` 开头，application 仅允许 chat/admin：

| 方法与后缀 | 行为 |
|---|---|
| GET config | 当前身份来源模式，不返回账号或配置引用 |
| POST login | 本地账号密码校验、显式映射、签发对应平台会话 |
| GET me | 从 Cookie 与当前服务端事实恢复安全用户视图和到期时间 |
| GET csrf | 访问凭证到期后恢复当前有效续期会话的 CSRF 值 |
| POST refresh | 验证当前事实、CSRF 并旋转续期凭证 |
| POST logout | 撤销当前会话，清除对应 Cookie |

成功会话响应仅含 User、application、expires_at、csrf_token，设置 no-store。失败沿用标准脱敏错误 Envelope、Request/Trace ID；不暴露用户名是否存在、密码、原始来源标识或 Token。公开 DTO/OpenAPI/前端类型由 `make contracts` 生成。

## 本地配置与迁移

1. `make db-upgrade` 应用 0003 迁移。
2. 运行 `uv run --locked python -m scripts.local_identity --username local-developer --display-name 本地测试用户 --application chat admin`，在终端输入不回显的至少 12 字符密码。命令为两个入口建立显式许可，不授予系统角色或业务权限。
3. 设置 `ENTERPRISE_RAG_LOCAL_IDENTITY_CONFIG_REF=.poc-results/auth/local.json` 后重启后端。私密文件不能提交，内部包含校验值与签名密钥；修改来源配置后需要重启 API。用户/身份状态和应用许可变更从数据库即时读取。

创建命令对同一配置使用跨进程文件锁，贯穿读取、查重、数据库写入和文件替换；拒绝已存在的账号，避免隐式重关联。数据库与私密文件不属于同一个原子事务；数据库已提交而文件替换失败时，命令失败且账号不能登录，需人工核对孤立映射，不能重试并自动合并。签名密钥更换会使旧访问凭证和 CSRF 值失效，应按会话撤销/重新登录流程处理，不承诺无缝轮换。

开发回退至 0002 会删除平台会话、续期历史、登录预算和应用入口许可，使所有平台会话失效。业务环境先停写并验证备份恢复，再选择前向修复；不得直接回退已使用的认证数据。预算窗口、到期/撤销会话和消费记录的定期物理清理随生命周期任务实现；当前不会用删除续期历史削弱重放检测。
