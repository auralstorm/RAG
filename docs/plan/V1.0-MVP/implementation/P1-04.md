# P1-04 登录与身份映射

日期：2026-11-26 更新。P1-04-01/02 已交付开发本地测试身份和双应用会话；按最新决策，当前补齐正式平台账号密码登录及受控 CLI 建号。飞书/OIDC 暂缓，未来沿用身份源 Adapter 与平台会话，不作为本次验收前提。

## P1-04-01 后端本地身份与平台会话

- `IdentityProvider` 是认证来源接口。本地 Adapter 从权限为 0600、属于当前操作系统用户的私密文件读取账号和 PBKDF2-HMAC-SHA256 校验值，每个账号独立 salt、600000 次迭代；未知账号仍执行同等密码计算。密码校验在线程中执行，不阻塞异步请求，也不长期占用数据库事务。
- 默认身份源未配置，`config` 返回 unavailable，登录服务返回 503；只有显式提供 `ENTERPRISE_RAG_LOCAL_IDENTITY_CONFIG_REF` 才启用。production 明确拒绝本地身份配置。账号不会在应用启动或登录时自动创建。
- 本地来源使用 `local`、精确 issuer 和不可猜测的稳定 subject 查 identities，再解析规范 users.id；不按用户名、显示名、email 或相同 UUID 合并。未建映射、来源停用、用户非 ACTIVE 或软删除均拒绝。
- 0003 迁移新增 identity_applications、auth_sessions、auth_refresh_tokens 和 auth_login_budgets。应用访问许可为当前服务端事实，Chat/Admin 会话分别绑定用途、Cookie 名和 JWT audience。identity_applications 只控制应用入口，不授予任何管理操作或 KB 权限；固定角色矩阵和资源 Policy 仍由 P1-05 交付。
- 访问 JWT 使用固定 HS256、`at+jwt` 类型、独立 issuer、每应用 audience，验证签名、必需字段、有效期、nbf/iat、格式和主版本。JWT 只保存会话、主体和身份引用；每次恢复仍核对数据库会话、当前用户、身份和应用许可，不信任 Token 中的角色。
- 默认访问期限 15 分钟，会话绝对期限 24 小时，不因续期延长绝对期限。续期使用独立随机凭证，数据库仅存 SHA-256；原凭证消费后不能再次使用，重放或并发重复续期撤销整个会话。客户端不得盲目重试续期请求，响应丢失时可能需要重新登录。
- Token 仅经 host-only、HttpOnly、SameSite=Strict Cookie 返回；不进入 JSON 或浏览器持久化存储。production Cookie 使用 Secure，本地 HTTP 开发使用非 Secure。Chat/Admin Cookie 名独立；Cookie 不以端口隔离，服务端额外校验当前应用的精确 Origin。
- 登录、续期和登出要求精确来源；跨应用、跨站或缺少 Origin 的写请求拒绝。续期和登出同时要求会话绑定的 CSRF 头；CSRF 值只给同源可读取的会话响应。访问凭证到期后，可通过只读 csrf 接口恢复内存值再续期；该接口不旋转凭证或授予登录。
- 当前用户停用、待离职、离职、身份停用或应用许可撤销均阻止恢复/续期。登出立即撤销服务端会话并删除对应应用 Cookie，不退出另一应用的独立会话。
- 登录预算持久化于数据库，默认同应用账号每 60 秒 5 次、同网络来源每 60 秒 30 次；`make dev-backend` 显式禁用 Uvicorn 代理头改写，不采信请求方的转发 IP。Nginx 同源代理场景在此模式下共享代理连接的网络预算；正式部署需先冻结可信代理链和限流位置，不能直接开放任意转发头。预算键为不可直接反查账号/IP 的派生摘要。成功和失败登录写入现有审计表；成功会话与成功审计在同一事务中提交，审计失败时不建立会话。完整审计应用服务继续由 P1-06 交付。

PyJWT 固定为 2.15.1，核对其官方 API 与 changelog 后沿用白名单算法、issuer/audience、require 与 strict_aud。HS256 安装不引入可选非对称加密依赖；对 SDK 未安装的可选 Key 类型引起的静态成员类型告警，仅在具体调用行忽略，解码结果仍经严格 Pydantic 校验。

## 身份源适配调整（2026-11-25）

原计划将飞书作为首个外部身份源；2026-11-26 已改为先使用正式平台账号登录，飞书接入按后续实际需求排期。以下 Provider/会话隔离仍保留，作为未来接入的扩展点：

- `domain/identity_providers.py` 定义带凭据类型的 `IdentityProvider`。本地密码凭据和授权码凭据分别建模，密码、授权码、nonce、PKCE 材料不进入 repr。跳转授权扩展接口仅定义授权地址构造和身份验证；具体厂商端点、参数与校验放在 Adapter，不让调用方模拟账号密码。
- `LoginService` 统一执行持久登录预算、事务外身份验证与失败审计；只有 Adapter 验证成功才调用 `SessionService.establish`。SessionService 不依赖厂商或密码，统一执行精确身份映射、当前账号/应用许可检查、会话建立与成功审计。HTTP 不接受外部身份键或直接签发平台会话。
- 授权码接口不是完整 OAuth 实现。后续登录协调流程必须将 state、浏览器、应用、Provider、过期时间和原始回调绑定到一次性服务端事务，原子消费后再进入 Adapter；Adapter 验证授权码和适用的 PKCE、nonce、签名、issuer/audience 等。具体采用哪些协议能力以飞书官方文档和实际验证为准。本次没有暴露可绕过这些检查的回调入口。
- `IamServices` 在装配入口分别提供平台会话、RBAC 和密码登录来源。后续 DTO 将 `AuthConfiguration.mode` 扩展为 `local/platform/unavailable`，其余 HTTP 登录/会话、Cookie、JWT 语义保持兼容；没有引入租户、自动账号合并或动态插件注册表。

平台会话密钥使用独立 `ENTERPRISE_RAG_AUTH_PLATFORM_CONFIG_REF`，引用私密 JSON 文件，字段为 `signing_key` 和可选 `pseudonymization_key`。显式引用存在时只使用该文件，文件缺失或无效直接启动失败，不能回退到旧密钥。生产禁止本地测试身份源；在完成数据库迁移且未配置本地测试身份源时，该密钥配置启用数据库平台账号登录。没有账号记录时仍无人可登录，应用启动和登录都不会自动创建账号。

旧的组合文件继续兼容，无需立即迁移。需要拆分时：

```bash
uv run --locked python -m scripts.separate_auth_config \
  --local-config .poc-results/auth/local.json \
  --platform-config .poc-results/auth/platform.json
```

该命令复制原有平台密钥，不更改源文件、不轮换密钥、不输出 Secret，目标文件使用 0600 且拒绝覆盖。不能因身份源选择变化而重新生成会话签名密钥，否则现有访问凭据/CSRF 会失效。

两个配置读取器共用有界的 owner-only 常规文件检查，拒绝软链接、FIFO、共享权限和超大文件。授权预算与外部验证仍不长期占用数据库事务。更换厂商时必须显式把新 ExternalIdentity 关联到原 User.id，不按邮箱/同名合并，RBAC 与业务归属继续引用平台用户。

## P1-04-03 正式平台账号密码登录

平台账号是当前首个正式身份源：用户名密码校验成功后返回精确的 `platform` identity key，再复用现有 `SessionService`、每应用 Cookie/JWT、登录限流、状态检查和登录审计。provider key 为 `platform`，issuer 为 `urn:enterprise-rag:platform`，subject 是不透明稳定 ID；不按用户名、显示名或 email 自动合并现有用户。

`0005_platform_password_accounts` 迁移新增 `platform_password_credentials`，账号用户名大小写不敏感唯一，数据库仅保存 Argon2id 编码校验值。密码校验在工作线程中运行，每进程最多并行四次；未知账号执行 dummy hash。数据库账号、身份、密码校验值、应用入口许可和创建审计在一个事务中提交。登录配置 DTO 新增 `mode=platform`；现有登录、会话、续期、CSRF、登出与错误响应保持兼容。

`scripts.initialize_platform_auth` 仅创建一次性 owner-only 会话密钥文件，目标已存在时拒绝覆盖。`scripts.platform_account` 通过终端不回显读取并二次确认初始密码，默认创建 ACTIVE 用户和 Chat 入口；`--admin-access` 才会同时开通 Admin 入口，并在审计快照记录应用范围。该命令不分配后台角色。首位管理员须明确使用 `--admin-access` 创建，再运行 `scripts.bootstrap_rbac --user-id <用户 UUID>`；初始化会检查 Admin 入口、无现存有效超级管理员、补齐伪名密钥并审计授予 SUPER_ADMIN。该离线运维流程允许生产使用，要求独立平台密钥文件，不提供 HTTP 匿名建号或首位管理员入口。

普通员工无需后台角色即可登录 Chat；没有 Admin identity application grant 的账号不能建立 Admin 会话。Admin 访问许可与用户角色仍为两项独立事实：有 Admin 入口但没有角色的账号不会获得 Admin 操作权限。P5-04 负责用户列表、界面建号/密码重置、停用和受审计的 Admin 入口/角色工作流；当前只提供 CLI 运维路径。未来添加飞书身份时，须显式关联既有 `User.id`，并独立授权该身份的 Chat/Admin 入口。

首次初始化示例：

```bash
export ENTERPRISE_RAG_AUTH_PLATFORM_CONFIG_REF=.poc-results/auth/platform.json
uv run --locked python -m scripts.initialize_platform_auth
make db-upgrade
uv run --locked python -m scripts.platform_account --username employee-001 --display-name 员工一
```

首位管理员额外显式设置 `--admin-access`，记录命令输出的 User UUID 后运行：

```bash
uv run --locked python -m scripts.platform_account --username administrator --display-name 平台管理员 --admin-access
uv run --locked python -m scripts.bootstrap_rbac --user-id UUID_FROM_OUTPUT
```

已有本地测试账号不会自动迁移为平台账号，也不会按相同用户名绑定；需要显式重新建号或后续由管理功能执行人工核验后的身份关联。开发环境若显式配置 `ENTERPRISE_RAG_LOCAL_IDENTITY_CONFIG_REF`，仍选择本地测试来源；清除此引用后才使用数据库平台账号。

## HTTP 入口

以下路径均以 `/api/v1/auth/{application}` 开头，application 仅允许 chat/admin：

| 方法与后缀 | 行为 |
|---|---|
| GET config | 当前身份来源模式（local/platform/unavailable），不返回账号或配置引用 |
| POST login | 当前已配置的密码身份源校验、显式映射、签发对应平台会话 |
| GET me | 从 Cookie 与当前服务端事实恢复安全用户视图和到期时间 |
| GET csrf | 访问凭证到期后恢复当前有效续期会话的 CSRF 值 |
| POST refresh | 验证当前事实、CSRF 并旋转续期凭证 |
| POST logout | 撤销当前会话，清除对应 Cookie |

成功会话响应仅含 User、application、expires_at、csrf_token，设置 no-store。失败沿用标准脱敏错误 Envelope、Request/Trace ID；不暴露用户名是否存在、密码、原始来源标识或 Token。公开 DTO/OpenAPI/前端类型由 `make contracts` 生成。

## 本地配置与迁移

1. `make db-upgrade` 应用 0003 迁移。
2. 运行 `uv run --locked python -m scripts.local_identity --username local-developer --display-name 本地测试用户 --application chat admin`，在终端输入不回显的至少 12 字符密码。命令为两个入口建立显式许可，不授予系统角色或业务权限。
3. 设置 `ENTERPRISE_RAG_LOCAL_IDENTITY_CONFIG_REF=.poc-results/auth/local.json` 后重启后端。私密文件不能提交，内部包含校验值与签名密钥；修改来源配置后需要重启 API。用户/身份状态和应用许可变更从数据库即时读取。

创建命令对同一配置使用跨进程文件锁，贯穿读取、查重、数据库写入和文件替换；拒绝已存在的账号，避免隐式重关联。数据库与私密文件不属于同一个原子事务；数据库已提交而文件替换失败时，命令失败且账号不能登录，需人工核对孤立映射，不能重试并自动合并。签名密钥更换会使旧访问凭证和 CSRF 值失效，应按会话撤销/重新登录流程处理，不承诺无缝轮换。

开发回退至 0002 会删除平台会话、续期历史、登录预算和应用入口许可，使所有平台会话失效。业务环境先停写并验证备份恢复，再选择前向修复；不得直接回退已使用的认证数据。预算窗口、到期/撤销会话和消费记录的定期物理清理随生命周期任务实现；当前不会用删除续期历史削弱重放检测。

## P1-04-02 双应用真实会话接入

- 两个应用各自持有独立 SessionStore、路由和应用用途。启动读取服务端 config，未配置身份源时继续显示禁用登录；local 模式展示明确标识的测试账号表单，platform 模式展示平台账号密码表单，不把本地来源称为企业 SSO。共享 CredentialForm 仅接收视图参数和回调，不发送认证请求；提交结束清空密码，卸载取消表单请求。
- 共享 api-client 使用实际生成 DTO 发送认证请求，保留 `/backend/` 代理前缀，Cookie 由浏览器接收，JSON 响应经过运行时校验。JWT 和随机续期凭证不写 localStorage、sessionStorage 或 JSON。原始错误和账号是否存在不进入页面。
- 启动从 me 恢复当前身份；访问 Cookie 到期而续期会话有效时，恢复 CSRF 并轮换续期 Cookie。成功后才映射 authenticated 和应用访问许可。身份撤销、停用、无权限和网络失败分别撤下受保护内容并进入已有状态界面。
- 焦点复查在后台执行，成功且主体未变时保留现有表单、草稿与页面状态；失效或主体变更时才撤下或重新挂载内容。页面卸载的迟到结果不能重新展示受保护内容。
- 同一应用使用 Web Locks 跨标签页串行处理认证操作，拿锁后先回查 me，发现其他标签已经续期就不重复旋转。同一 Store 合并焦点/定时检查，不取消已发出的认证写请求后再盲目重放。
- 同源 localStorage 只保存不含 Token 或用户 ID 的拒绝重放标记（操作种类及公开的旧到期时间）；发出续期/登出前写入，确认响应后清除。响应未知或标签关闭时保留；其他标签据此拒绝重放，直到服务端确认较新的访问凭证或用户重新登录。此标记只能阻止操作，不能授予认证权限。浏览器不支持 Web Locks 时不自动续期，访问到期需重新登录；协调存储不可写时拒绝会话变更，不降级为不安全的重试。
- 两端均有退出登录入口，先撤下当前页面，再等待对应服务端会话撤销。退出 Chat 不退出 Admin。登出结果未知时显示恢复提示，不报告成功或自动恢复旧页面。后续业务客户端接入新 API 时仍需按 401/403 规则重新验证身份与权限。
