# P2-01 Provider 管理

日期：2026-11-26。本次交付 Provider 管理 API、Admin 列表与表单、凭据加密和事务审计；模型注册及真实调用依赖 P2-02，模型子表依赖 P2-07。本记录不关闭完整 P2/M2，也不将已有纯规则测试当作真实供应商调用证据。

## 实现与权限

Admin 的 `/admin/providers` 使用 ProTable 的查询区、工具栏、状态、分页和列设置，遵循用户指定的 [Ant Design Pro table-list](https://github.com/ant-design/ant-design-pro/blob/master/src/pages/table-list/index.tsx)。继续使用 Vite、React、antd 与 ProComponents，没有引入 Umi。页面负责组装，表单、操作与请求生命周期位于 `modules/modelGateway`；表格代码按需加载。

`GET/POST /api/v1/admin/providers`、`GET/PATCH/DELETE /api/v1/admin/providers/{provider_id}` 均通过当前 Admin 会话及 PolicyEnforcer。超级管理员拥有 `provider.manage`，审计员只有 `provider.read`，知识库管理员和普通员工拒绝访问，Chat 会话不能作为 Admin 会话使用。配置文件缺失时管理接口返回 503，不回退为明文存储。

写入要求可信 Origin、当前 CSRF、`confirm=true` 和 `expected_policy_version`；编辑、启停与删除还必须携带读取时的 `expected_config_version`，过期或并发编辑返回 409。变更、版本快照、加密凭据与成功审计处于同一 PostgreSQL 事务；审计失败整体回滚。拒绝与冲突追加安全审计，不记录配置正文或凭据。更新不会因未知网络结果自动重放；页面关闭编辑器、清空凭据并提示回查。

名称、类型、Base URL、超时、代理、备注和启停状态已覆盖。创建默认启用；启停和删除独立确认，表单提交要求显式确认。Base URL 拒绝用户名、密码、Query 和 Fragment；凭据拒绝空值及 Header 控制字符。API 只返回是否配置 API Key/代理，不返回 Key 尾号、长度、密文或 SecretReference。管理专用 DTO 额外提供可编辑的 Base URL、超时、备注与代理配置状态，原有公共 Provider 契约保持不变。

## 存储与兼容

迁移 `0006_provider_registry` 新增：

- `providers`：当前配置、SecretReference 列、备注及软删除标记。
- `provider_config_versions`：每次创建、编辑、启停和删除的私有不可变快照；数据库触发器阻止改写或删除历史版本。
- `provider_secrets`：按 Secret ID/版本/环境保存 AES-256-GCM 密文和加密主密钥版本。
- `provider_proxy_configs`：代理配置的私有加密凭据引用。

API Key 和代理地址使用独立随机 nonce；AAD 绑定 Secret ID、版本与运行环境，篡改密文或替换引用均拒绝解密。替换 Key 增加 Secret 版本，历史快照仍绑定原引用。删除执行软删除并停用，列表和详情不再返回该配置，历史与加密凭据保留，不级联清除未来模型的引用。当前没有实际 models 表，不探测或伪造后续模型依赖；P2-02 应以外键保留引用，调用时重新读取当前 Provider 状态与固定版本，拒绝软删除或停用项。

新增 `cryptography==48.0.1`，锁文件提供本机 Intel macOS 可安装的 wheel。原有登录、角色权限和公开 Provider 标识不变，无存量 Provider 数据需要迁移。应用迁移会新增表；回退迁移将删除本任务所有配置与密文，须先完成备份与影响确认。

## 初始化与密钥维护

开发环境先运行 `make db-upgrade`，然后创建一次性私密文件：

```bash
uv run --locked python -m scripts.initialize_provider_secrets --config .poc-results/providers/secrets.json
```

在本机 `.env` 设置 `ENTERPRISE_RAG_PROVIDER_SECRETS_CONFIG_REF=.poc-results/providers/secrets.json` 后重启 API。初始化使用 O_EXCL，不覆盖已有密钥；读取仅接受当前操作系统用户拥有的普通文件、0600 等无他人权限模式，拒绝符号链接和过大文件。生产将文件置于受控 Secret 挂载目录，路径从部署配置注入，不存入 Git/VITE_*。

主密钥文件与数据库必须配套备份。`active_key_version` 指定新写入使用的密钥，`keys` 保留旧版本供历史解密。轮换时在私密配置中添加新的随机 32 字节 base64url 密钥和不同版本名，保留旧版本，安全替换文件后重启；已经写入的密文不会自动重加密。不要通过重新运行初始化覆盖旧文件，也不要删除仍有密文引用的旧主密钥。此流程只实现主密钥分版本读写，不声称已经实现在线重加密或自动备份恢复。
