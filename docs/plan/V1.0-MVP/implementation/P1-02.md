## P1-05 接续：当前权限联调（2026-11-25）

- 公共 api-client 新增当前权限读取，使用既有 `/authorization/{application}/me`，保留代理前缀、HttpOnly Cookie、no-store、10 秒期限与取消。响应运行时校验应用、规范主体、Policy 版本、权限码及角色视图；不按角色名推导权限，不接受通配操作码。
- CapabilityView 增加安全的 `subject_id`，取自同一次服务端授权事务的规范 User.id。前端必须与刚确认的会话主体相同，避免另一个标签切换账号后拼接旧主体与新权限。它不是外部身份 ID、Token 或可复用的授权凭据；后端仍为每次业务操作重算当前权限。
- 启动恢复、登录成功和会话刷新后，先读取并确认权限再发布 authenticated。页面聚焦和 60 秒定时重新校验；后台请求期间可保留尚未到期内容，原 Cookie 到期时独立计时撤下，慢请求不会延长展示期限。浏览器定时器受后台节流影响，界面撤权不是服务端推送；后端每次受保护请求仍检查当前事实。401 清理并进入登录流程，403 撤下内容，503/无效响应展示安全错误，均清除旧权限；取消或旧代响应不能恢复已卸载的状态。
- 前端 SessionState 的授权视图仅保存当前 Policy 版本和操作码，在内存中使用，不写 localStorage/sessionStorage。主体或 Policy 版本变化重挂载受保护子树，清理原页面数据、草稿和请求。
- Admin 当前只有工作台路由，要求 `dashboard.read`；普通员工即使有 Admin 应用入口也不会看见检查连接入口。三种固定后台角色按服务端操作码进入；没有引入未来 Provider/角色/ACL 管理页面。Chat 应用入口不要求已有 KB Grant，避免没有知识库的员工无法进入；真实知识内容、检索和引用继续按后续用例校验资源 ACL。
- 权限不足和状态查询失败界面仍可退出当前应用会话，避免没有工作台权限时陷入返回登录又重定向的循环；退出继续使用服务端会话撤销和应用隔离。

## 本次交付

- 两个应用固定使用 React Router 8.5.3，Node/React 及类型 peer 要求与仓库锁定版本兼容。采用数据路由，业务页面按匹配路由加载；页面加载与加载失败有安全提示。
- Chat：`/` 进入 `/chat`，缺少登录态时转 `/login`。企业账号登录按钮仅在绑定真实登录回调后可用；当前服务未接入，显示明确提示。开发模式可从登录页进入 `/preview`，该路由和模拟来源在生产模式不开放。
- Admin：`/` 进入 `/admin`，缺少登录态时转 `/login`。管理员账号和密码表单具备标签、必填校验、提交中和失败状态；服务未接入时禁用字段和提交。密码仅为表单临时值，提交结束清空，卸载清理，不写浏览器存储或日志。
- 公共 UI 提供 AccessScreen、SessionProvider、SessionBoundary，接收展示状态与回调，不创建身份或请求认证 API。应用根节点管理 Ant Design Provider，具体页面布局由各应用负责。
- `SessionState` 是前端视图类型，与后端 User/status、AccessContext、Token 和 HTTP DTO 分开。应用未来从可信服务端响应映射 checking、anonymous、authenticated、forbidden、error。authenticated 必须有主体 ID 和当前应用访问许可，缺失许可或 ID 拒绝展示受保护内容。
- 匿名和过期会话转到登录页；检查中、权限不足、状态查询失败分别展示清楚的状态。主体变化重新挂载业务内容，会话撤销后撤下内容并清理页面请求。URL 参数与 localStorage 不参与登录判定。
- 登录回调只表示请求发起/完成，不自行将状态改成 authenticated。重复提交由本次请求引用抑制，卸载通过 AbortSignal 通知取消，迟到错误不覆盖页面。不展示供应商错误详情。
- Admin 工作台增加 Ant Design 原生 Table：稳定 rowKey、两列服务连接事实、初始空态、检查中、确认成功、失败及重试。真实请求使用公共 api-client 的 `/health/live`；10 秒超时，重复请求受控，卸载取消，失败清除旧结果，保留合法 Request ID。只显示 API 进程可响应，不将 liveness 说成认证成功或依赖就绪。
- Admin 开发 `/preview` 仅提供上述公开连通性检查，入口带开发标识；生产移除预览路由和链接。预览不构造登录态，也不访问管理业务数据。真实仪表盘指标继续按后续任务交付。
- 两个应用各自装配 API Client，读取公开 `VITE_API_BASE_URL`，默认 `/backend/`；开发 Vite 代理和部署 Nginx 代理转到后端，避免把跨域失败当成业务失败。公共客户端保留代理前缀、拒绝含凭据或非 HTTP(S) 地址，不增加认证协议或 Token 存储。

源码入口见 [Chat 路由](../../../../frontend/apps/chat/src/routes/routes.tsx)、[Admin 路由](../../../../frontend/apps/admin/src/routes/routes.tsx) 和 [公共访问布局](../../../../frontend/packages/ui/src/AccessScreen.tsx)。
