# P1-06 操作审计基础能力

日期：2026-11-25。按 V1.0 MVP 的 P1-06 验收，交付统一追加写入、当前权限保护的查询，以及登录/角色/权限变更的定位字段和失败控制。沿用 P1-03 的 audit_events 与防修改触发器、P1-04 的平台会话及 P1-05 的统一 Policy，不增加平行审计表或远程日志系统。

## 写入与安全事件

- `audit/domain/recording.py` 定义仅有 audit(event) 的 AuditWriter 与 AuditContext；`audit/application/recording.py` 从明确字段构造 AuditEvent；`adapters/audit_writer.py` 提供唯一的 PostgreSQL 追加实现。认证与 RBAC Repository 共享此实现，事务仍由原 Application 用例拥有，Writer 不自行 commit，不吞掉失败。
- 登录成功记录规范 User.id、当前有效角色 ID/系统角色快照、UTC 时间、直接 ASGI 连接 IP、模块对应的动作、结果、风险与 Request/Trace ID。登录风险为 MEDIUM，角色/权限变更为 HIGH。未知账号、密码错误、身份映射/状态拒绝和预算限流均记录 DENIED；未认证主体不按客户端用户名猜测，不记录账号、密码或来源 subject。
- 角色创建/修改/删除、角色分配与 ACL 变更沿用 P1-05 的成功及 DENIED/FAILED 审计，补齐直接 IP；已有目标 ID 的拒绝和冲突也记录所选对象。未成功创建角色时没有对象 ID，不将请求中的名称/权限码原样保存为摘要。
- 登录及全部六个 RBAC 写入口的缺失/非匹配 Origin、Sec-Fetch-Site 跨站拒绝，在返回 403 前提交匿名 DENIED。RBAC 缺失、伪造、用途不匹配、未知、撤销或过期凭据造成的会话验证拒绝，在返回 401 前提交同类事件。每个请求只追加一条，记录服务端选定的动作、可用目标 UUID、直接连接 IP 与 Request/Trace ID；操作者为空、角色快照为空、前后摘要为空，不读取无效凭据中的身份。凭据已完成验证而随后发生的权限/CSRF 拒绝继续记录可信操作者。
- 摘要只接受 AuditSnapshot 的明确字段：权限 ID、角色 ID、启用状态、单条 Grant 与用途等。凭据、原始请求、Token、密码、API Key、供应商文本与私有身份来源键不进入审计 JSON。请求关联上下文只关联链路，不授予身份或权限。
- IP 只解析 request.client.host；不做 DNS 解析，不采信 X-Forwarded-For、X-Real-IP 或客户端 X-Request-ID。非 IP/Unix 测试连接记 null，旧记录也保持原 null。现有 `make dev-backend` 使用 `--no-proxy-headers`；反向代理下记录的是 ASGI 直接连接，真实终端 IP 需部署时先冻结可信代理链，不能直接信任任意转发头。

当前关键安全写操作成功和成功审计在同一 PostgreSQL 事务提交。登录审计失败不会创建会话，权限审计失败不会提交角色/授权变更；依赖错误返回脱敏 503，不报告成功、不自动重试未知写入结果。逻辑拒绝/冲突继续通过 savepoint 回滚，再提交 DENIED/FAILED 事件。数据库/审计自身不可用时无法宣称失败事件已落库，本版本采用失败关闭，不虚构补偿队列。

本任务覆盖已实现的登录、角色与权限变更用例，包括上述 Origin 与会话验证早期拒绝。DTO 校验在路由用例之前返回 422，本任务未将其转换为安全动作审计；会话读取、续期/登出的安全语义沿用 P1-04，未扩充动作枚举。未配置身份/审计服务或数据库/审计不可用时，不能保证事件落库；已配置路径的追加失败返回脱敏 503，不能冒充已记录的 401/403。Provider、Model、KB、配置、生命周期和高危身份溯源的事件在各自真实用例交付时接入同一端口。

## 查询接口

`GET /api/v1/admin/audit-logs` 只接受当前有效 Admin Cookie；同一数据库事务中加载当前角色/Policy 并要求 audit.read，查询后再次检查有效期。SUPER_ADMIN、AUDIT_READONLY 以及显式获授 audit.read 的自定义角色可查询；KB_ADMIN/无权限主体 403，未认证 401，配置/依赖不可用 503。Chat Cookie 或伪造的角色头不能授予读取权限。读取需要匹配的 Origin（若请求携带）且拒绝跨站来源。

| 参数 | 语义 |
|---|---|
| page / page_size | 默认 1 / 20，每页最多 100 |
| module | iam、provider、model、kb、rag、trace、lifecycle；由已冻结的 action 前缀派生 |
| action / result / risk | AuditAction、SUCCEEDED/DENIED/FAILED、LOW/MEDIUM/HIGH 的精确匹配 |
| actor_user_id / object_id | 规范平台操作者 / 动作目标 UUID，精确匹配 |
| request_id / trace_id | 安全关联 ID 精确匹配，Trace ID 保持非零 32 位小写十六进制 |
| occurred_from / occurred_until | 含时区的 UTC 归一时间，包含起点、不含终点；同时填写时必须递增 |

返回现有 PageResponse，每条 AuditLogView 保留 AuditEvent 字段并增加派生 module；按 occurred_at DESC、id DESC 确定顺序。总数和当前页在一个 SQL 语句快照内读取，空页保留真实匹配总数；并发追加后的后续分页可能自然变化，不承诺跨请求快照。筛选值绑定参数、列名限定为服务端白名单；数据库锁/语句超时均为 5 秒，超时失败关闭。

响应设置 no-store。私有 protected_reason_ref 不进入 SQL 的公开投影或响应；身份溯源日志只展示动作目标 Trace ID，不把受保护原因或被溯源身份加入响应。读取历史摘要也经过严格 AuditEvent/AuditSnapshot 校验，发现未知或敏感字段时返回 503，不直接传出原始数据库 JSON。事件仍使用 schema_version="1.0"，旧事件无需回填。

公开 HTTP 仅提供 GET，没有追加、编辑、删除或清空审计的业务端点。数据库现有 UPDATE/DELETE/TRUNCATE 触发器继续拒绝篡改，PUBLIC 无审计表权限。数据库所有者/超级用户具有离线修改结构的权力，不能把此实现描述为密码学不可篡改存储；生产账号分权、备份及合规保留按部署验收落实。当前没有自动清理审计数据的任务或员工删除级联。

## 兼容与验证

本任务没有新 migration，不回写既有事件，不改变权限矩阵或身份来源配置。数据库仍为 `0004_rbac_policy`；新登录与权限变更自动补齐字段，旧审计不伪造 IP/角色。OpenAPI 与生成的 TypeScript 同步更新，api-client 导出 AuditLogView，双应用继续使用现有契约。审计管理页面随后续 Admin 功能交付，本任务为 Backend 基础能力。

专项覆盖当前授权和撤权、Chat/Admin 隔离、直接 IPv4/IPv6 与伪造转发头、登录失败/限流、角色快照、Request/Trace 定位、成功/拒绝/冲突、筛选与并列时间排序、私有原因隐藏、DB/API 防修改、畸形历史摘要及审计失败回滚。早期拒绝专项从真实 HTTP 入口检查六个 RBAC 写路由与双应用登录，验证事件唯一性、匿名字段、动作/目标/IP/关联、无权限业务变更以及登录预算不被 Origin 拒绝消耗；包含携带真实管理员标识的错误签名 JWT、Chat 用途凭据和撤销/过期会话，不从无效凭据推断操作者。认证/RBAC 回归覆盖共享 Writer 替换后的既有安全行为。
