# P1-01 后端工程底座

## 本次交付

- Alembic 和 SQLAlchemy 按 `uv.lock` 固定。Alembic 使用既有 psycopg 驱动连接 PostgreSQL。基线 `0001_baseline` 记录版本，身份与权限表由 P1-03 交付。迁移进程持有 PostgreSQL 事务级锁，避免同一数据库的两个迁移进程同时变更版本。
- `postgres_transaction` 为每次调用管理一个 psycopg 异步连接。正常退出提交，异常退出回滚，两种情况均释放连接。持久化适配器使用用例持有的连接，Repository 在具体模块中定义。
- `test_module_boundaries.py` 检查 Python 静态导入。API、Application 和 Domain 拒绝直接依赖具体数据库或外部 SDK，模块之间拒绝访问对方的私有 Infrastructure。
- HTTP 错误、请求关联、分页和生成契约沿用 P0 的公共底座。排序与过滤规则随实际列表接口验证。[HTTP 契约](../../../api/README.md)

## 本地操作

```bash
make db-upgrade PROFILE=development
make db-current PROFILE=development
```

迁移由维护命令执行。数据库配置沿用选定环境的应用设置，连接凭据通过驱动传入。开发库回退可用 `uv run --locked python -m scripts.migrate_database downgrade <revision>`，目标版本须显式提供。P1-03 将按业务 DDL 验证升级兼容与回退策略。

## 验证结果

- `make check` 通过，覆盖 247 项后端测试、9 项前端测试、双应用构建、模块依赖规则和 API 契约校验。
- `make infra-test` 通过。使用真实 PostgreSQL 的独立空库验证迁移升级、重复执行、回退、再次升级，以及事务提交、异常回滚和连接释放。测试结束清理临时数据库。
- `make db-current PROFILE=development` 成功查询开发库版本并报告当前尚未应用迁移。
