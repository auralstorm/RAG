## P0-04-01 公共 HTTP 契约

本地验收通过。首个分项交付 API Error Envelope、请求关联上下文、分页参数/响应，以及真实 OpenAPI、独立 JSON Schema 和前端生成类型的同步检查，来源及行为见 [契约制品入口](../../../api/README.md)。它同时落实 P1-01 中与此契约直接相关的 HTTP 错误处理与 Request/Trace ID 中间件。

- Error 固定 code、公开 message、服务端 request_id、retryable、脱敏 details；HTTP/校验/未知异常统一映射，原始输入和异常 detail 不进入响应或摘要日志。
- 请求使用纯 ASGI 中间件，成功/失败响应均携带关联头；W3C 父上下文只用于关联，已开始的流异常不会改写 HTTP 状态或追加 JSON。
- PaginationQuery 使用 page/page_size，默认 1/20，上限 100；PageResponse 包含 items/total/page/page_size 并验证基本数量约束。尚无实际数据库列表消费者。
- OpenAPI 来自实际应用路由；JSON Schema 来自 Pydantic DTO；前端生成类型由公共 api-client 导出。`make contracts` 更新，`make contracts-check` 拒绝制品漂移，`make check` 覆盖全部现有消费者。
- 生成工具在私有构建包使用其支持的 TypeScript 5.9.3；应用和客户端仍按原 TypeScript 6.0.3 检查。依赖与锁文件对应，不使用全局忽略压制 peer 不兼容。

本分项无数据库变更或数据迁移；live/ready 原有成功和就绪响应保持兼容，公共 HTTP 错误改为已设计的 Envelope。前端保留 HttpError.status，增加受验证的错误字段与关联信息。

## P0-04-02 身份、角色、权限与 AccessContext

本地验收通过。源码此前没有 IAM 表/迁移或实际身份路由；对本项目开发 PostgreSQL 的只读盘点返回 0 个业务基础表。逻辑设计差异按 [统一契约 2.1](../../../architecture/统一契约与跨版本演进规则.md#21-v10-平台主体与身份授权契约) 与 [身份/授权详述](../../../api/iam-policy-contracts.md) 记录，本轮无数据库变更或存量 ID 重写。

- 新增 User、ExternalIdentity、SubjectBinding、Role、Permission、UserRole、RolePermission、ResourceGrant 的版本化契约；规范 User.id 与既有管理员/员工 UUID 显式关联，不按同名/同值自动合并。
- 身份解析模块按已核验 provider_key/issuer/subject 或明确来源类型/ID 解析当前 ACTIVE User；重复、缺失、停用与非活跃状态拒绝，错误只携带稳定代码。
- AccessContext、AuthorizationSnapshot 与 PolicyDecision 明确当前主体/身份、环境/用途、Policy 版本和有效时间；操作权限与 KB Grant 同时校验，当前用户/身份停用、成员移除、Grant 撤销或版本变化均重新判断。
- 原 ADMIN_USER/EMPLOYEE/ROLE/GROUP Grant 类型保留，USER 明确指向规范平台主体；旧来源无映射时不能因 UUID 相等而获得访问权。MANAGE 包含 READ，READ 不包含 MANAGE。
- Schema Catalog 统一生成公共与内部 Schema，公共 IAM 类型由 api-client 导出；内部原始身份键、关联与授权事实不进入前端类型或真实 OpenAPI。

纯授权接口不会创建用户、会话、Token 或业务端点；固定角色默认矩阵、当前事实数据库读取、事务一致性与真实 Policy→Retriever 集成在 P1 及对应模块阶段验收。Docling 实际解析验证继续按用户决定留待 P3-01。
