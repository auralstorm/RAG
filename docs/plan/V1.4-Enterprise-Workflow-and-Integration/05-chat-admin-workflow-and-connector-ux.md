# 05｜Chat、Admin、审批与 Connector UX

> 版本：V1.4。沿用 Chat/Admin 双入口，API/权限见 [06](06-database-api-and-contract-design.md)，业务语义见 [01](01-workflow-engine-and-execution-architecture.md) 与 [03](03-approval-center-and-business-action-governance.md)。

## 1. 用户角色与入口

Chat 承载业务申请、自己的流程进度、审批待办和结果。Admin 承载流程/连接器/审批策略管理、发布、运维与受控对账。复用既有用户、角色、匿名 Trace 和审计界面，不增加第三个一级产品入口。

角色按组织 RBAC/资源授权配置：普通申请人、审批人/受托人、业务 Owner、流程开发者、Connector 管理员、运维处理人、只读审计员。审批人不因拥有 decide 权限而获得 Connector 配置或 workflow.publish 权限。

## 2. 工单申请与结果

申请表单按已发布输入 Schema 展示标题、业务描述、分类/优先级等已冻结字段；字段/组织范围来自服务端。提交前展示“创建申请，审批通过后写入外部工单系统”的实际影响及可见范围。

Draft、Workflow Instance、外部工单分别显示标识：申请已提交、审批中、写入处理中、等待结果确认、结果不确定需处理、已确认工单创建。只有服务端确认外部效果后才展示“创建成功”及外部工单引用。

Agent 可以协助填写草稿，用户核对后提交；费用/人事/权限等高风险字段不因模型建议自动获准。重复点击或刷新重试复用 Idempotency-Key，发布版本变化不使同一申请重复创建。

结果链接由服务端生成并受控访问；权限撤销后的旧链接不继续暴露内容。确认失败时显示业务事实与下一步处理，不用模糊“系统异常”掩盖外部可能已经提交。

## 3. 进度与事件

实例详情显示公共状态、当前步骤、审批阶段、Deadline、外部确认/补偿摘要和 Trace ID。SSE 断线通过 instance_id/sequence 补拉，重复事件按 ID 去重；时间线从数据库重建。

暂停/取消按钮依状态与授权展示。取消页面提示已提交/确认的业务效果及可能的补偿，提交取消请求后显示“取消处理中”，服务端尚未闭合前不显示“已撤销外部工单”。

展示结构化业务步骤和记录，不展示模型隐藏思维链、凭据或未授权调用参数。

## 4. Approval Center

审批待办包含申请人、请求内容、待批准动作/目标、最终参数摘要、风险、当前阶段/分配版本、有效期、委托来源及审计链接。批准前可查看授权范围内的参数详情，UI 不计算最终 Hash 或授予权限。

批准/拒绝须理由与幂等 Key；提交携带当前 Assignment revision，服务端校验真实审批人。已被升级/转交/决定的待办显示状态变更并回查，不能继续提交旧页面决定。

组 all 显示固定候选集合和已有决定；阶段批准与整项请求批准分开呈现。委托显示有效期/范围，管理员调整分配记录原因；超时明确 expired，不用“自动处理”暗示自动批准。

撤回入口说明时点影响：未提交动作可取消，已提交动作需对账/补偿。评论和流程解释不会改变正式 ApprovalDecision。

## 5. Admin 工作台

| 页面 | P0 能力 | 核心限制 |
|---|---|---|
| Workflow 列表/编辑 | 元数据、受控 JSON/表单、版本 Diff、校验、发布/暂停/回滚 | 已发布内容不可原地修改；引用和 Gate 服务端校验 |
| 运行实例 | 状态、步骤/Attempt、外部引用、取消/恢复 | 按实例/组织 ACL；操作附原因及当前 revision |
| Connector 管理 | 配置引用、工具能力、健康、准入证据、轮换/停用 | 明文 Secret 不读取；健康与生产启用分别显示 |
| 审批策略/分配 | 组、阶段、委托、升级和有效期 | 有效规则版本固定，调整分配有审计 |
| 对账/补偿 | UNKNOWN 证据、只读回查、受控确认与补救 | 无证据不能标成功；补偿独立授权/审批 |
| 质量/审计 | Workflow 回归报告、Gate、操作审计 | 复用 Evaluation/Audit，敏感数据按既有策略访问 |

任意 Graph/BPMN 拖拽、复杂报表和更多厂商配置向导为 P1/后续，P0 使用可验证的受控编辑方式即可完成流程管理。

## 6. 对账与恢复交互

NEEDS_REVIEW 页面明确展示外部提交 Attempt、最后确认结果、工单/请求引用、允许的查询与处理动作。操作员提供外部证据与结论，服务端检查 reconcile/compensate 权限和当前状态，不提供任意改状态的万能按钮。

补偿申请显示原成功操作、拟补救内容、不可逆限制和审批要求。完成后分别呈现原事实及补偿结果，不把创建历史删掉或把失败补偿显示为成功回滚。

## 7. UX 验收

普通申请人只能访问授权实例；审批人只处理当前 Assignment；审计员只读；Connector 管理与审批决定权限分离。覆盖表单错误、加载/空态、401/403、并发冲突、SSE 断线、重复提交、审批过期、UNKNOWN、取消在途和补偿失败。

页面状态、操作能力与服务端一致；外部工单成功有确认依据，失败/等待原因和下一步处理可理解。Mock 数据和生产结果明确标识，UAT 使用业务确认的真实角色与试点系统。
