# 05｜质量治理、可观测与 Admin 运营

> 版本：V2.0。复用 Dataset/Profile/Runner/Gate、OpenTelemetry/Phoenix 和 Audit；新增公共字段/API 见 [统一契约](../../architecture/统一契约与跨版本演进规则.md) 与 [07](07-database-api-and-contract-design.md)。

## 1. 统一质量治理

RAG、Agent 和 Workflow 继续使用现有 target_type、版本化 Dataset/Profile/评分器和结果模型；V2.0 增加资源/Workspace、路由/价格/环境与安全/恢复的适用配置。企业资源权限/容量/灾备测试可使用受控 platform 目标 Adapter，旧 Runner 不识别新目标时安全拒绝，不能静默按 Agent 执行。

每项 Gate 固定目标版本、数据集、指标分母、评分器、环境、随机性/并发及阈值。版本发布、模型/Prompt/索引/Tool/Policy 变更触发适用回归；安全、审批、预算及副作用用确定性证据，语义 Judge 不代替这些边界。

线上采样遵循授权/隐私/保留，反馈生成待评审样本和诊断；不能直接自动改写已发布配置或审批规则。漂移告警记录变化版本、范围、对比条件和处置，避免不同环境/数据集的指标被误比较。

## 2. SLI/SLO

M0 定义目标业务、统计窗口、成功/延迟条件、容量、故障处理与责任人。至少分别记录：平台 API、RAG 首 Token/完成、Agent/Workflow 接受/完成/等待、模型/Connector、定时器/恢复及资源授权指标。

| 指标视角 | 必须区分 |
|---|---|
| 用户端到端 | 符合业务结果/时限的 eligible 请求；供应商失败也反映在用户体验指标 |
| 平台阶段 | API/队列/检索/模型/外部动作/确认/恢复的独立耗时与错误 |
| 等待 | 审批/事件/模型限额等待与实际执行，不能合成单一“慢服务”结论 |
| 正确性 | 引用/ACL/审批/预算/重复效果/UNKNOWN 等安全与业务事实 |
| 数据完整性 | 迁移/删除/恢复、丢失请求/重复事件/费用调整及可重建性 |

错误预算和告警根据已确认 SLO 与真实窗口计算，采用趋势/多窗口等适当机制减少噪声；不能先声明固定可用率再倒推通过。用户指标与平台诊断都保留，不能把外部依赖错误全部剔除来美化结果。

## 3. Trace、Metrics 与 Audit

Trace 关联 资源/Workspace 的受控引用、request/admission/route/usage、Run/Workflow/Step、Approval/Action/外部 Key 和 Recovery Epoch。默认匿名、敏感字段摘要化；高危溯源继续受控，不复制完整 Secret/正文。

Metrics 记录容量、租约、Outbox/Timer、模型路由、预算预留/未知用量、UNKNOWN/补偿、恢复/删除及供应商质量。避免将用户 ID、任意 request_id/operation_key 放入无界 Metrics 标签；逐请求诊断留在受控 Trace/记录。

业务 Audit 记录管理/授权/发布/审批/对账/补偿/跨范围/撤权/恢复操作，并保存原因、策略和前后摘要。Trace、Metrics 与 Audit 具有不同事实/隐私/留存用途，不能相互取代。

## 4. Admin 与 Workspace 体验

| 工作台 | 运营能力 | 授权/事实要求 |
|---|---|---|
| Workspace/成员 | 当前范围、资源、角色与分享 | 明确 资源/Workspace，切换经服务端验证 |
| Model/Route/预算 | 版本、候选能力、限额、已确认/估算/预留/待核对费用 | 路由不扩大权限，预算调整与账目分离 |
| Runtime/容量 | 实例/队列/租约/Timer、扩缩容与告警 | 显示实际范围/状态，操作按现有控制契约 |
| Quality/Gate | 回归、漂移、评分失败与版本差异 | 可比条件明确，缺分不能显示通过 |
| Security/Lifecycle | 事件、Key 轮换、导出/删除/保留、员工撤权 | 最小权限、审批/理由、部分完成与验证分离 |
| Recovery/Upgrade | Recovery Set、演练、Read-only/写入准入状态和兼容性 | 外部事实未核对时不显示“完全恢复” |

平台运营员访问企业内部资源仍需显式范围、目的及对应权限；企业审计员只查看授权内容。Admin 展示本企业组织、成员和资源治理，停用与恢复限制对运营员可解释。

用户 Chat 保持清晰的可用/额度/权限/等待/结果提示，不暴露数据库锁、内部审批 Token 或 SDK 细节。相关技术诊断仅在受控 Admin 中提供。

## 5. 处置与验收

处置可以按已批准策略限流、停用不合格候选、冻结新写入/发布和回退配置指针，边界/审批/预算仍生效。历史实例、模型费用和外部动作不会因 UI 回滚消失。

测试覆盖错误窗口/分母、供应商故障、标签基数、Trace 隐私、跨范围查询/导出、可比回归/缺分、预算差异、在线漂移、恢复未闭合与管理操作权限。报告包含真实环境、版本、样本、负载与处置证据，未冻结目标保持“待确认”而不是绿色通过。
