# 06｜备份、灾备、恢复与升级治理

> 版本：V2.0。恢复/Journal 方案见 [ADR-0012](../../adr/0012-recovery-reconciliation-before-side-effects.md)，公共对象/状态见 [统一契约第 11 节](../../architecture/统一契约与跨版本演进规则.md)。业务 RPO/RTO、地域和数据保留在 M0 冻结。

## 1. Recovery Set

Recovery Set 是可验证的关联集合：DB Snapshot/WAL 范围、对象/产物 Manifest 与 Hash、索引/配置/Agent/Workflow 版本、密钥/Secret 恢复引用、资源授权/删除标记、预算账本/预留及独立操作证据。保存实际捕获时刻/游标和恢复覆盖，不能仅写“数据库备份成功”。

大对象与索引可能非同一时点完成，须记录与 DB 引用一致的版本或重建策略。ES 只有业务数据/解析产物/模型和索引配置齐全时可按计划重建；维度/向量空间、Alias、ACL/归属重新验证。

Secret/加密密钥不放进普通 Manifest/日志，恢复所需版本由独立受控渠道保存和验证。删除/停用 tombstone、法律保留和旧 Token/权限策略不能因回滚快照被遗忘。

## 2. RPO/RTO 与故障档位

分别确认平台读、生成/计费、业务写入、Workflow/审批、DB/对象/索引/消息与地域故障的 RPO/RTO；依赖恢复和外部对账时间也计入业务 RTO。

| 场景 | 需要验证 |
|---|---|
| API/Worker/节点故障 | 冗余接管、当前租约/授权/预算与幂等 |
| DB/队列故障切换 | 写主防分裂、事务/Outbox/消费恢复，不重做未知业务动作 |
| 误删/损坏/PITR | 恢复点/对象/配置完整性、当前访问规则、后续业务效果及费用核对 |
| 整体部署/地域故障 | 独立恢复依赖、数据驻留/密钥/网络、故障域和实际覆盖 RPO/RTO |

跨地域复制和自动多活不默认启用；根据明确需求、存储/供应商/许可和故障试验决定。备份频率不是 RPO 实测值，启动服务时间也不是完整业务 RTO。

## 3. Side Effect Journal 与费用证据

DB 恢复可能丢失已提交 Action/幂等行，而外部工单/模型调用仍已发生。V2.0 在可产生业务效果/费用的操作前保留独立可恢复的提交意图及后续确认，记录原 request/Action/admission/Attempt、Owner/资源引用、operation_key、参数/配置/价格 Hash 和外部引用。

流程：先持久化原 Action/预留 → 写 INTENT 并取得符合选定故障域/恢复策略的 durability receipt → 当前 Gate/授权/预算通过 → 执行原操作 → 追加确认/用量证据。持久凭证不可取得时停止新外部副作用，不偷偷退回无记录写入。

INTENT 表示“可能已发出”，不证明未发送或成功。响应后本地/Journal 写入失败转 UNKNOWN/待核对；原 Key、Action/Attempt ID 保持，网络重试/补偿分别按旧版本协议执行。

Journal 的存储/versioning/防篡改/地域、receipt 和恢复验证依真实对象/审计 Adapter 冻结；不能因单次写成功宣称跨地域零丢失。最小内容、加密/权限、输入引用和保留按数据制度管理。原输入/密钥不可恢复时不重建新参数继续执行。

## 4. 恢复流程与准入

```mermaid
flowchart LR
  Stop[隔离旧执行者 / 阻止新副作用] --> Restore[恢复 Recovery Set]
  Restore --> Verify[数据 / 密钥 / 当前权限 / 删除规则验证]
  Verify --> Read[允许已验证范围只读]
  Read --> Reconcile[外部 Action / 模型费用 / 在途记录核对]
  Reconcile --> Gate[写入与计费准入验证]
  Gate --> Release[新 Epoch 放行并观察]
```

1. 限制请求与 Worker，隔离/撤销旧执行者的写能力，创建新的 deployment_epoch。新的 Epoch 防旧节点推进状态，不能重置外部 operation_key。
2. 根据 Recovery Set 恢复 DB/对象/配置/密钥/索引，校验引用、游标、Hash、归属和当前访问规则；缺失范围保持不可用。
3. 重新应用当前停用/删除/身份撤权规则；完成授权验证后只读放行已验证范围。历史查询可用不意味着生成模型调用或业务写入可用。
4. 从 Journal/WAL/外部可信证据识别恢复点后的 Action/Attempt/费用窗口，回填原 ID/Key 和 UNKNOWN/预留，去重已有记录；证据不足保持受限待核对。
5. 业务系统按原 operation_key 查询事实，不能用新 Instance/Key 重做丢失记录。模型调用使用 Provider/账单/Journal 证据恢复预留和结算，未知费用不能自动释放。
6. 准入确认当前 Policy、Secret、Grant、预算/幂等、定时器/Trigger/Outbox 和所有恢复范围闭合，才释放副作用/计费 Worker。恢复失效的审批按当前规则重新确认，不能用旧批准扩大权限。
7. 记录 scope、指标、尚受限能力、Operator、证据和观察窗口；整体通过须满足单企业部署的业务恢复目标。

没有可信外部查询或独立操作证据时，相关写入保持关闭并人工处置，不能把数据库启动当作所有业务恢复成功。

## 5. 在途恢复与取消

Workflow/Agent/Timer 以原状态与快照恢复，当前 Deadline/授权/预算仍生效。重复 Outbox/事件按原 ID 去重；迟到回调结合原 Owner、Hash、分配/期限和新 Gate 验证。

旧批准或 Grant 无效时暂停新业务动作，但保留已发生效果；补偿需独立授权及原成功事实。已撤权、停用或删除的旧实例不能因灾备恢复重新获得执行权限。

## 6. 升级与回滚

每次发布包含 API/Event/DB/索引、资源授权、配置/路由/价格、Agent/Workflow/审批策略、预算/Journal 和部署 Epoch 的变更清单。先 Expand/兼容消费者/数据验证，再收紧约束/结束窗口。

灰度按已授权范围和配置版本进行；应用/指针回滚保留业务、费用和副作用事实，不能破坏性 downgrade 清空去重/预留/等待。跨旧新 Worker 的 Owner/租约/序列/资源上下文保持兼容。

## 7. 演练与交付

演练覆盖真实恢复依赖、失效密钥、缺失对象、PITR 后外部已创建工单/已收费但本地记录丢失、权限/删除回滚、未知预留、重复队列、旧节点迟到及跨故障域恢复。

证据记录恢复点、故障域、组件/业务目标、恢复集合、原 Key 核对、身份/权限/费用/审批检查、实际 RPO/RTO 与受限范围。Restore Runbook、值班负责人、备份检查/恢复计划和生产 Gate 都是交付物；测试工具或一次成功样例不能替代完整演练。
