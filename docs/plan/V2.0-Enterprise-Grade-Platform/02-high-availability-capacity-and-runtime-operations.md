# 02｜高可用、容量与 Runtime 运营

> 版本：V2.0。公共控制与租约增量见 [统一契约第 11 节](../../architecture/统一契约与跨版本演进规则.md)，故障恢复与写入准入见 [06](06-backup-disaster-recovery-and-upgrade-governance.md)。具体拓扑和 SLO 在 M0/压测冻结。

## 1. 故障域与部署原则

继续使用模块化业务边界，按负载/故障隔离拆执行进程；拆微服务或迁移 Kubernetes 需要容量、团队或隔离收益依据。开发 Compose 不能代替跨宿主机/故障域高可用验收。

| 层 | 高可用与事实边界 |
|---|---|
| API/入口 | 多实例、健康路由、滚动发布；会话/权限/请求幂等不依赖单进程 |
| Worker | 分类型/资源池处理 Ingestion、Agent、Workflow、Evaluation/对账；租约、重试与预算持久化 |
| PostgreSQL | 已验证复制/备份/故障切换、连接池和写主防分裂；事务是状态/预算事实 |
| RabbitMQ | 版本/环境验收的复制队列、发布确认与消费确认；重复投递仍需业务幂等 |
| Redis | 限流/缓存冗余及重建；不可用时依据策略保守限流/拒绝，不能丢预算账本 |
| Elasticsearch | 副本/分片、容量/恢复、受控索引版本；故障不放宽 资源 ACL |
| 对象/Secret | 可用性、版本/保留和密钥恢复依实际方案；引用不会自动提供灾备 |
| 外部模型/系统 | Deadline、隔离池、候选路由、对账；恢复不能提升权限或重做未知副作用 |

跨区域多活并非默认 P0；按业务 RPO/RTO、数据驻留、依赖一致性和实际故障域决定。单故障域冗余与区域灾难恢复分别验证。

## 2. API 与状态

API 从持久实体/缓存恢复会话、SSE 游标、当前主体、资源授权上下文，实例重启不改变 Run/Workflow ID。liveness、readiness 和依赖状态分开；模型供应商异常可降级对应生成路径，不能伪造健康或让不相关管理 API 全部不可用。

认证/撤权依可信源；权限或密钥系统不可用时敏感操作失败关闭。入口限制连接、请求体、并发、排队时间及重试提示；超载返回明确可解释结果，不通过无限排队隐藏失败。

SSE 断线使用原资源 ID/sequence 补拉或回查；重连不创建第二 Run 或重复 Workflow。实例发布绑定服务/Schema 兼容窗口，旧客户端未知状态按统一规则安全处理。

## 3. Worker、队列与公平性

每类执行池有系统上限和 部门/Workspace/用户/资源维度的配额；在线、评测、入库和对账分池或分队列避免资源争用。配额与优先级不能跳过发布/审批/预算/资源授权。

领取任务验证数据库 Owner、当前状态、Deadline、Policy 和额度；使用租约/心跳与递增 fencing_token，旧 Worker 回写不能覆盖新执行者。外部调用在事务外，原 Key 和操作事实已保存；租约防并发推进不代替外部防重复。

发布确认失败由 Outbox 修复，消费确认丢失按任务/事件 ID 去重。DLQ 保留引用、失败类型、来源版本和重试次数，重放需要当前资源授权和安全状态；不得用更高权限服务身份批量盲重放。

长审批/Timer/未知提交释放 Worker 执行槽，保持持久等待与占用的有效预算；过期不意味着外部没有费用/副作用。退避、重试次数、Deadline 贯穿 API/任务/模型/工具。

## 4. 容量与伸缩

M0 记录用户/请求分布、文档/索引规模、并发 SSE、模型 RPM/TPM、长 Workflow、评测负载、外部接口限额及峰值假设。压测关注排队/执行/供应商延迟分布和 DB/ES/内存饱和，不能只用平均值或最高单次吞吐。

伸缩基于队列等待/积压、活跃租约、模型/工具并发及 CPU/内存等多维信号；扩大 Worker 不能突破供应商/数据库/系统与用户硬限额。冷启动/抖动/缩容的迟滞规则经测试冻结。

缩容/发布先停止新领取，再等待有界执行或持久化安全恢复点；未知外部提交转对账，不能强行重置 Key。Scheduler/Timer Dispatcher 使用领导者或分区协调，重复扫描通过 DB 条件更新防重复发生。

## 5. 故障运营与验收

分别演练宿主机/API/Worker 故障、DB 切换、MQ 丢确认、Redis 故障、ES 降级、模型限流和外部响应丢失，记录可用性、等待/恢复、预算/幂等及数据完整性。

恢复模式需新的 deployment_epoch 防止旧执行者重新写入；新 Epoch 不重建外部 operation_key。故障后任意恢复路径仍验证当前主体/资源授权、审批、预算和外部事实。

运维交付有容量基线、扩缩容/积压/DLQ/租约/供应商故障 Runbook、告警负责人、发布/恢复和 SLO 报告。关键指标按真实目标验收，增加容器数量本身不是高可用通过证据。
