# 09｜V2.0 完整实施计划与验收

> 里程碑不等于固定工期。任务见 [08](08-code-structure-and-development-backlog.md)，契约/API 见 [统一规则](../../architecture/统一契约与跨版本演进规则.md) 和 [07](07-database-api-and-contract-design.md)。实际人力、部署/数据/供应商、指标及制度在 M0 冻结。

## 1. Entry Criteria

现有 RAG/Agent/Workflow、Tool/Policy/身份、审批/Grant、外部 Action/UNKNOWN、Checkpoint/Timer/Outbox、Evaluation/Audit/Trace 与数据库/队列/对象存储有真实可复用能力和上游验收证据。

V1.4 工单流程类型已确认，但具体系统/生产验收尚需实际记录；设计文档齐全不代表运行能力已经完成。前置缺项进入具名补齐任务，不在 V2.0 重建平行基础模块。Multi-Agent 仍按场景准入，不阻断与其无关的运营任务。

## 2. M0 冻结项

| 项目 | 当前依据/状态 | 需要的证据 |
|---|---|---|
| 产品部署 | 所有版本单企业内部独立部署，ADR-0013 accepted | 企业内组织/成员/资源清单及原 ACL |
| 上游业务 | 工单申请→审批→外部创建→确认 | 真实接口/审批/幂等/补偿/账目及兼容数据 |
| 部署/云拓扑 | 实际地域/故障域/编排方式待核验 | 数据等级、企业制度、容量、成本/运维与 POC |
| 身份/Secret/网络 | 既有边界，配置待核验 | 来源/成员/服务 Scope、轮换、驻留与恢复依赖 |
| 价格/计量/预算 | 持久预留/账本设计草案 | Provider 能力、单位/币种/价格/账单/未知处理与严格上界 |
| SLO/容量 | 无已确认实测目标 | 业务窗口/分母/成功/延迟、负载、Owner与验收条件 |
| RPO/RTO/Journal | ADR-0012 proposed | 故障档位、恢复集合、独立持久凭证/密钥/外部核对及真实演练 |
| 数据制度/安全 | 企业要求待落实 | 保留/删除/员工撤权/合法保留、审批、跨范围运维与事件恢复 |

没有证据的参数保留待冻结状态；通用代码/Fake 技术验证可推进，相关生产指标不能签通过。单企业范围已确认，更高灾备等增强需求以具体证据评审。

## 3. M0–M8

### M0：范围、数据、契约与 POC

任务 A-01–A-08。交付单企业部署范围、资源/Key/消费者清单、Schema/OpenAPI/Event/Migration 计划、真实环境/目标及 ADR-0011/0012 评审。

Exit：Owner/依赖/验收明确；跨 Scope、预算/未知提交和恢复边界没有相互冲突口径；供应商/制度/生产缺项具名，不补造数值。进入具体生产环境前，相关资料与准入证据须齐备。

### M1：企业内部成员与资源权限

任务 B-01–B-06。交付复用的企业组织/Workspace、可信成员与主体、旧入口兼容、资源/索引/缓存/对象/队列/凭据授权及存量回归。

Exit：旧 ID/Key/快照/ACL/费用不变义；本企业多用户/角色/KB/Workspace 的正负向授权通过；历史无 Workspace 的资源按原 ACL 服务，缺必需身份或权限时拒绝。

### M2：高可用、执行池与容量

任务 C-01–C-06；C-07 仅在条件批准后实施。交付 API/Worker 状态独立、真实故障域、DB/MQ/对象/Secret 验证、租约/Epoch、隔离池、排队/缩容/恢复及容量报告。

Exit：单实例/节点/依赖故障可解释恢复，旧执行者不覆盖当前状态，外部 Key/审批/预算保持；负载/可用/延迟达到已确认目标。只扩容容器不能签高可用通过。

### M3：路由、额度、计量与对账

任务 D-01–D-08；D-09 为条件增强。交付受控路由、价格源、多级预留/派发、用量 Ledger、未知预留与账单对账、旧 Run 兼容视图。

Exit：候选能力/区域/权限/索引/评测约束生效；并发准入不超分配；重复来源不重复费用，取消/失联/TTL 不退款未知提交；严格上界无依据时拒绝相应调用。

### M4：安全、生命周期与员工撤权

任务 E-01–E-06；E-07 按正式要求。交付受限管理、Secret/网络/轮换/恢复、Security Incident、Hold/删除/员工撤权与恢复 tombstone、真实制品风险检查。

Exit：越权/泄露/未批准写入失败关闭；必要审计/账目与个人正文分开保留；旧备份恢复后不复活已删除/撤权数据；未知业务效果和费用闭合有受控路径。

### M5：质量、SLO 与运营 UI

任务 F-01–F-06；F-07 为增强。交付统一多目标 Gate、平台检查/漂移、真实 SLI/SLO、受控 Trace/Metrics/Audit、Workspace/成本/安全/恢复 Admin。

Exit：指标分母/环境/可比条件和隐私/基数明确；缺分不能绿色通过；UI 与当前授权/预算/业务事实一致；只读/部分恢复不显示完全恢复，自动处置不能改企业审批或历史配置。

### M6：Recovery Set、Journal 与恢复准入

任务 G-01–G-06。交付实际集合/密钥/对象/配置/账目/操作证据、提交前 durability receipt、新 Epoch、读/写 Gate、PITR 后外部事实/费用核对、跨版本恢复/回滚及演练。

Exit：丢本地去重/预留时仍不重复工单/漏费用；Journal INTENT 不冒充未提交，未知继续持有/对账；当前 Policy/删除/审批/期限重新应用；实际恢复范围/RPO/RTO 符合目标，否则相关准入保持关闭。

### M7：全链路迁移、故障和业务验收

复核 B-06、C-06、D-08、E-06、F-06、G-04–G-07。实际旧 API/用户、Webhook/Timer/审批、路由/费用、数据迁移、Secret/备份和工单流程在限定环境联调，形成可重复 Runbook、指标/差异/剩余风险记录。

Exit：全部 P0 的升级/企业资源权限/恢复/业务和安全证据通过；实际制度/供应商未确认项不签生产完成；剩余差异有负责人与处理时点。

### M8：单企业生产发布与观察

完成 G-07 的真实单企业试点、容量/SLO/数据/费用/恢复/运维签署。G-08 仅按更高灾备需求单独准入。

Exit：全部 47 条 P0 已验证，生产观察/暂停/回滚/外部补救与值班明确。P1 增强按实际选择记录证据，不能冒充基础交付已经包含。

## 4. 验收矩阵

| 领域 | 必测场景 | 判断依据 |
|---|---|---|
| 资源权限 | 历史无 Workspace 资源、跨用户/角色/KB/关系/ID、授权缺失/伪造、缓存/索引/对象/消息 | 当前服务端授权，无资源泄露/错误归属，Key 不重建 |
| 高可用/容量 | API/宿主机/DB/MQ/Redis/ES/供应商故障、缩容/旧租约 | 真实故障域、恢复时间、无重复推进/外部效果 |
| 路由 | 未授权模型/地区/能力/上下文、Embedding/Judge fallback | 候选约束、索引向量空间、可比评测保持 |
| 预算/费用 | 多级并发、重复来源、取消/失联/未知 usage、价格修正/币种 | 原子准入、持久预留、唯一 Ledger 与可核对金额 |
| 安全/撤权 | 权限/Secret/注入/合法保留、在途 Action、删除/旧备份恢复 | 事实和当前制度一致，无无限留存或复活数据 |
| 质量/运营 | 分母/缺分/漂移、标签基数/Trace 隐私、错误/部分恢复 UI | 真实指标/范围，确定性 Gate、授权界面 |
| 灾备 | 密钥/产物缺失、PITR 失去 Action/费用、旧节点/重复队列 | 原 Key/Journal/外部核对、未知保持受限、实际 RPO/RTO |

先以 Fake Clock/Provider/Connector/Journal 验证边界行为，再验证真实 DB/锁/队列/存储/独立恢复与供应商协议。文档/示例检查不能替代这些运行验收。

## 5. 发布、指标与 DoD

发布先兼容制品/资源迁移 → Scope 与副作用/费用影子验证 → 固定路由/价格/额度/安全策略 → 真实恢复演练 → 单企业试点 → 业务/安全/QA/运维签署和观察。

记录业务 SLO、排队/恢复/对账、未批准写入/重复效果、Scope 泄露、未核对费用/预留、删除/恢复和外部依赖；严重安全/副作用失败不能由平均指标抵消。目标/环境/版本/分母和实际结果全部保留。

最终 DoD：单企业资源权限、容量/高可用、路由/预算/费用、安全/生命周期、质量/运营、灾备/升级与真实业务通过；生成制品、代码/数据、Runbook 与文档一致。更高灾备和认证按批准范围声明。
